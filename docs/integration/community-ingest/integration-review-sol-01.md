## 보안·데이터·UX 판단

- **서버 경계:** user JWT 검증 뒤에만 service-role RPC를 호출한다. SQL은 `security definer`를 사용하되 anon/authenticated/PUBLIC의 내부 RPC와 private 표 권한을 회수한다(`MAP server/ingest/handler.ts:125-132,137-162`; `MAP supabase/migrations/202609260200_community_ingest.sql:148-156,547-559`). auth도 동일하게 owner/session을 확인한다(`AUTH server/account.ts:131-143`; `AUTH supabase/migrations/202609260100_community_account_registry.sql:381-393`). 후보 테스트는 위조·만료·비카카오·무동의·세션 변경·철회 토큰을 거절하고 원장 수를 확인한다(`MAP tests/integration/community-stack.test.ts:162-261`). 우회가 확인된 서버 경로는 없다. 다만 전체 §14 매트릭스 통과라는 주장에는 위의 Realtime/Storage 및 응답 JSON 공백이 있다.
- **CORS·rate limit·비밀:** ingest CORS는 정확한 origin 목록이며 wildcard가 없고, user 및 connection별 분당 제한을 RPC로 적용한다(`MAP server/ingest/handler.ts:101-108,137-162`; `MAP supabase/functions/community-ingest/index.ts:16-35`). auth account는 user당 제한을 적용한다(`AUTH server/account.ts:141-143`). 후보 실스택은 account 429만 유발한다(`MAP tests/integration/community-stack.test.ts:293-299`); ingest 429·CORS 악성 origin 시험은 없다. Edge 로그는 event/action/result/난수 trace 중심이고 본문·토큰을 기록하지 않는다. PC 세션/연결 비밀은 별도 암호화 파일이고 모바일 연결 비밀은 난수 32바이트다(`PC services/community_auth_store.py:1-11,40-42`; `M lib/community/gate/community_gate.dart:472-476`). PC·모바일 빌드 변수는 공개 URL·publishable key만 받고 `sb_secret_`/`service_role`를 거부한다(`PC scripts/build/build_exe.py:22-42`; `M build_android_common.sh:131-196`). **운영 산출물의 실제 문자열 스캔은 이번 검토에서 미실행**이다.
- **불변 capture·금액·동등성:** PC journal은 개인 DB 쓰기 전 기록하고 실패 시 해당 신고 저장을 건너뛴다(`PC core/storage/reports_repo.py:194-269`). 모바일 정상 경로도 공식 파서 출력과 공식 주소 지오코드로 DTO를 만들고 개인 보강 전에 journal을 쓴다(`M lib/services/sync_engine.dart:683-740`). 확정 금액만 문법으로 파싱하며 추정 금액을 DTO에 넣지 않는다(`PC services/community_capture.py:92-111,215-232`; `M lib/community/capture/observation_rules.dart:120-160,230-285`; `PC PROJECT_RULES.md:37-40`). 세 언어는 같은 관측 벡터의 payload/canonical/SHA를 비교한다(`MAP tests/product/communityContract.test.ts:11-32`; `PC tests/test_community_contract_vectors.py:29-49`; `M test/community/contract_vectors_test.dart:21-40`). event_type 결정은 앱 단위 벡터, `source_report_key`는 서버 계산과 PC·모바일 실스택 prefix 비교다(`MAP server/ingest/handler.ts:191-195`; `PC tests/test_community_live_stack.py:148-149`; `M test/community/live_stack_test.dart:135-136`). **같은 실제 공식 상세 응답을 두 앱 파서에 넣고 event_type까지 왕복 비교하는 실경로 테스트는 없다.**
- **개인 DB·rebuild:** 후보 diff는 개인 DB의 공유용 테이블/컬럼을 늘리지 않고 `community.db`를 별도 저장소로 둔다(`PC services/community_store.py:24-83`; `M lib/community/community_store.dart:17-76`). 그러므로 PC `PROJECT_RULES.md` §3-1의 양방향 개인 DB 컬럼 동기화 의무를 새 스키마 변경으로 발생시키지 않는다. PC 복원은 교체 전 회전 실패를 전파한다(`PC core/storage/exchange.py:347-352`). rebuild는 목록에 없는 기존 행을 지우지 않는 병합을 지향한다(`PC services/community_rebuild.py:405-459`; `M lib/community/rebuild/community_rebuild.dart:55-75`). 모바일 복원은 H-02 때문에 같은 보장을 하지 못한다.
- **게이트 UX:** 로그인과 공유 동의는 별도 상태이며 로그인만으로 진입하지 않는다(`PC services/community_gate.py:82-102`; `M lib/community/gate/community_gate.dart:211-280`). PC 체크박스는 초기 `checked`가 없고 동의 버튼은 체크 전 비활성, 모바일은 `_consentChecked = false`다(`PC web/templates/components/community_consent_card.html:22,143-146,184-191`; `M lib/screens/community_onboarding_screen.dart:41,496-522`). PC 미들웨어는 method+path allowlist, 모바일은 홈 게이트를 권한 화면보다 먼저 둔다(`PC main.py:306-370`; `M lib/main.dart:123-169`). 원격 철회 뒤 중앙 fact는 즉시 비공개이고 새 ingest는 거절된다(`MAP supabase/migrations/202609260200_community_ingest.sql:173-180,224-247`; `MAP tests/integration/community-stack.test.ts:239-261,404-431`). WS 연결 중 `verification_required`가 되면 기존 `/ws/events`를 4403으로 닫지 않는 M-01은 예외다.

## 운영 반영 전 수동 확인

1. 대상 운영 프로젝트에 `MAP scripts/integration/preflight_counts.sql:1-32`를 읽기 전용으로 실행하고 공개 legacy v2 fact가 있으면 전환 migration 결정 전 중단한다. 합성 이력·SHA 확인 후 auth `202609260100` → map `202609260200` 순서로 적용한다. `migration_paths.sh`는 운영 DB에서 실행하지 않는다(`MAP docs/integration/community-ingest/deployment-and-rollback.md:3-16`).
2. 중앙 함수 `community-account`·`community-ingest`의 `verify_jwt`, `AUTH_JWT_ISSUER`, origin allowlist, 공개/비밀 키 분리와 policy hash를 실제 호스팅 설정에서 확인한다. 호스팅 Kakao 로그인·callback/redirect·Supabase 세션·동의·철회·삭제·익명 공개 API를 운영자 제한 계정으로 확인한다. 공개 전 `ready` 전환은 제한 업로드 결과 확인 뒤다.
3. Android/iOS 실기기에서 첫 화면→카카오→기본 해제 동의→권한 요청 순서, 앱 종료/재개·딥링크, 자정 KST 백그라운드, 오프라인/철회, DB 복원·재수집을 확인한다. PC 실행파일·Docker와 모바일 릴리스 산출물에서 동의문 포함 및 비밀/원번호 문자열 스캔을 다시 수행한다. auth 브라우저 증거도 **고정 후보 commit**의 스크린샷·클릭·console/network와 함께 확인한다.

**병합 조건:** H-01~H-03과 M-01을 수정하고 관련 실패 주입·기존 WS 테스트를 통과시킨다. §20의 부분 게이트를 실제 스택 증거와 후보 문서로 닫은 뒤 같은 고정 commit을 다시 검토한다. 현재 네 목표 브랜치 병합은 승인하지 않는다.
