## 3. §25.2 중점 1~11 판정

1. **필수 gate·동의·콜백:** PC `main.py`의 middleware와 community gate, 모바일 첫 화면 gate 및 auth 콜백/상태 경로를 대조했다. 검사한 경로에서 명확한 무동의 통과는 찾지 못했다. 실기기 딥링크·기존 사용자 세션 및 브라우저 전 경로 동적 검증은 이 감사에서 미실행이다.
2. **초기화·백업·복원:** `community_rebuild` checkpoint/marker와 dataset 회전 계약, 양쪽 DB 교환·복원 코드를 추적했다. **SOL-02~05**가 데이터 손실·복구 결함이다. 계획 S-03의 ‘개인 저장 전 source capture, `personal_save_state`와 전송 가능 여부 독립’은 의도된 계약이므로 그 순서만으로 finding을 만들지 않았다.
3. **환경·JWT·session·writer:** 인증 `account.ts`·`relay.ts`, 지도 ingest handler와 양 저장소의 service_role 전용 SQL/RLS·REVOKE를 대조했다. 본 범위에서 직접 권한 우회나 비밀키 커밋은 확인하지 못했다. **SOL-10**은 함수 자체의 요청 크기 보호가 뒤늦게 적용되는 문제다. 실제 배포 secret 주입은 검증 대상 외다.
4. **실시간·수동·자정·ACK:** PC/모바일의 capture→journal→outbox→ACK와 manual/midnight/recovery 호출을 비교했다. **SOL-01**에서 모바일 ACK 후 반복 전송을 확인했다. 원천 캡처가 개인 저장보다 먼저라는 점은 승인 계약과 일치한다.
5. **KST·scheduler·OS lifecycle:** PC `CronTrigger(00:00, Asia/Seoul)`과 `schedule_runs`, 모바일 KST due key·Workmanager 등록/dispatcher를 읽었다. 코드상 자정 키 및 중복 억제 경로를 확인했으나 모바일 OS가 실제 정시에 실행한다는 증거는 없고 iOS 실기기 실행은 미검증이다.
6. **실제 ingest·private/RPC·idempotency:** 지도 함수의 `getUser`/claims 검증, 인증 registry와 지도 migration의 권한 제한·락, 이벤트별 ACK와 revision 비교를 읽었다. 해당 경로에서 재현한 직접 privilege bypass는 없다. 운영 DB에 직접 쓰거나 로컬 실행 스택 DB를 변경하지 않았으므로 실환경 다중 기기 경쟁은 독립 재현하지 않았다. **SOL-10**은 ingest 입력 크기 경계에 해당한다.
7. **공개 지도·분모·마스킹:** private fact→공개 DTO, plate mask와 날짜별 집계·클라이언트 사용을 읽었다. **SOL-06~08**이 날짜 축/결측 및 전체 목록 노출의 기능 결함이다. 확인한 DTO에는 private 원문/식별자 직접 출력이 없었고 번호판 정규화 후 2/4/6자리 마스킹을 확인했다.
8. **저장소 간 계약·배포:** PC↔모바일 DB 양방향 변환, auth↔map SQL/RPC, 배포 순서를 대조했다. **SOL-02~03**은 DB 계약 위반, **SOL-09**는 정리 후 합성 검사 경로 문제다. 운영 migration 적용·공개 설정의 실제 값은 확인하지 않았다.
9. **커뮤니티 외 변경:** 기간 내 저장 계층·통계·별점·파서·테마·백업/복원·모바일 DB 변환·크롤러 diff와 관련 호출 경로를 위험 중심으로 검토했다. **SOL-02~05**는 커뮤니티 기능 밖 데이터/복원 회귀다. 확정/추정 과태료 필드 분리 경로는 코드상 확인했으나 모든 금액 화면과 내보내기의 실기기 종단 검증은 하지 않았다.
10. **미연결 UI·mock·skip·문서·패키징:** **SOL-08**의 목록 API 미연결, **SOL-05**의 복원 주석과 실제 보존 동작 불일치, **SOL-09**의 검사 문서/경로 불일치를 확인했다. r5의 passed/skipped 요약만으로 실기기·브라우저·운영 연동 통과를 선언하지 않는다. demo mode와 production mode 분기, Android/iOS 빌드 설정을 읽었지만 독립 배포 빌드는 실행하지 않았다.
11. **병합·worktree·권한:** `merge-and-cleanup-first.md`의 네 목표 HEAD/tree와 실제 detached HEAD, 범위 commit/file 목록을 대조했다. 감사 시작 시 지도 worktree는 clean이었다. 현재 확인한 결함을 contributor worktree에만 있는 수정으로 간주하지 않았다. 원격 미push commit과 실운영 반영은 이 감사의 승인 범위 밖이며, remote PR의 추가 코드는 조회하지 않았다.

## 4. 종합

**높음 3건(SOL-02, SOL-03, SOL-04)을 포함한 미해결 finding이 있으므로 완료·배포 가능 아님.** 특히 서버↔모바일 DB 교환은 사용자 규칙 3-1을 만족할 때까지 양쪽을 함께 수정·왕복 검증해야 한다. 이 보고서는 수정 commit이나 Sol 재검증 결과를 선기입하지 않았다.
