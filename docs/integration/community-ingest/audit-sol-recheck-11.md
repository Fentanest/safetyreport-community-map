## 직접 확인한 삭제·보존 경계와 새 회귀

`/tmp`의 성공 시작에서는 `crawl_control.start_crawl()`가 만든 고유 파일을 가짜 자식 시작 함수에 전달했으며, 시작 함수 안과 성공 반환 뒤 모두 파일이 존재했다. 보고 없는 직접 완료 처리를 뒤이어 호출하면 파일만 정리되고 대기열·재시도 타이머는 생기지 않았다. 별도 실패 시작에서는 기존 성공 실행 파일 하나를 남겨 둔 채 새 시작을 거짓으로 돌렸고, 실패 실행의 파일만 사라져 기존 파일은 유지됐다. 이는 `_discard_queue_file`이 **성공 시작 파일을 지우지 않는다**는 독립 확인이다.

미해결 기록 저장 실패 때 남긴 `.done.json`은 고유 실행 경로에 묶여 있어 다음 실행의 보고를 오염시키지 않는다. 다만 기동 회수가 없으므로 **파일 보존은 사용자 통지가 아니다**. 장애가 해소돼도 서버가 이 파일을 다시 읽지 않으며 `/crawl/status`에도 항목이 추가되지 않는다. 이 차수 diff에서 중대·높음의 새 회귀는 발견하지 못했지만, R9-02를 닫았다고 판정하지 않는 이유다. `crawl_control`은 `start_crawl` 호출의 예외·거짓 반환을 정리하지만, 파일 생성 후 그 호출에 도달하기 전의 예외까지 모두 정리하는 것은 아니다; 남은 고유 파일은 자동 재크롤에 사용되지 않는 보관/정리 문제로 본다.
