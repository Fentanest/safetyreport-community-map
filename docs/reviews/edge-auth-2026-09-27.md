# Edge 함수 사용자 인증 점검 · 2026-09-27

## 적용할 계약

지도 통계, 내 통계, 신고 업로드, 계정 API는 호출자의 유효한 Supabase 사용자 세션을 확인한다.
통계 지도는 추가로 카카오 신원·활성 공유 동의·지도에 올라간 본인 신고 1건 이상을 확인한다.
`community-auth-relay`는 PC·Docker의 **로그인 시작 전** 중계이므로 사용자 JWT 예외다. 요청별
일회용 비밀과 요청 상태를 확인하며, 세션 연결 완료(`/complete`)는 사용자 JWT도 검증한다.
브라우저 `OPTIONS` 사전 요청과 거절 오류 응답에는 통계·계정 자료를 담지 않는다.

## 운영 읽기 전용 확인

Supabase CLI `functions list`에서 다섯 함수 모두 ACTIVE. 무인증 HTTP 관측:

| 함수 | 플랫폼 `verify_jwt` | 무인증 요청 | 판정 |
|---|---:|---|---|
| `public-analytics` v4 | false | `GET /meta` → **200**, 버전·coverage 등 반환 | **FAIL: 운영 재배포 필요** |
| `my-analytics` v4 | true | `GET /compare` → 401 | PASS(무인증 차단) |
| `community-ingest` v2 | true | `POST {}` → 401 | PASS(무인증 차단) |
| `community-account` v3 | true | `POST /status` → 401 | PASS(무인증 차단) |
| `community-auth-relay` v2 | false | 형식 오류 `POST /requests {}` → 400 | 합의한 로그인 시작 예외; 성공 요청은 capability 검증 필요 |

`my-analytics`의 무인증 CORS `OPTIONS`는 204와 지정 Origin·Authorization 허용 헤더를 반환했다.
운영 `public-analytics`가 200인 직접 원인은 운영 설정값 또는 배포 코드 조합이며, secret 값은 읽지 않았다.
현재 저장소의 이전 코드는 `ANALYTICS_ACCESS=public`일 때 인증을 건너뛰도록 되어 있었다.

## 로컬 후보와 검사

- `server/publicHandler.ts`: 접근 설정을 필수로 하고 익명 공개 분기를 제거. 모든 통계 경로에서
  `getUser`·JWT claims·사용자 세션·공유 자격을 데이터 조회 전에 검사한다.
- `supabase/functions/public-analytics/index.ts`: `ANALYTICS_ACCESS` 공개 스위치를 제거.
  `supabase/config.toml`과 합성 manifest에서 `public-analytics verify_jwt=true`.
- 무인증·publishable key만 있는 요청은 모든 통계 경로에서 401, 가짜/타인/만료·비카카오·무동의·무업로드 요청은 거절하는 테스트를 유지한다.
- `npm test`: 207 passed, 28 skipped. `npm run build`, `npm run scan`, Python product tests 11개,
  `compose_supabase.mjs check`: 통과. 합성 배포 후보 `/tmp/cm-auth-gated-compose-20260927-2302`는
  함수 5개 중 사용자 전용 4개 `verify_jwt=true`, 로그인 중계만 `false`로 생성됐다.
- 로컬 Chrome의 비로그인 지도 진입은 모의 OAuth로 자동 이동, 통계 요청 0건, 취소 시 접근 안내로 복귀.
  실제 카카오 사용자 로그인과 운영 contributor 200은 **NOT_RUN**.

## 운영 반영 결과

사용자가 Edge + GitHub main + Pages 반영을 승인했다. 합성 후보
`/tmp/cm-auth-gated-compose-20260927-2302`에서 **`public-analytics`만** 운영에 배포했다.
운영 `functions list`에서 `public-analytics` v5는 ACTIVE, `verify_jwt=true`다. 나머지 네 함수의
버전과 설정은 위 표 그대로다. 다른 Edge 함수·운영 SQL·secret은 변경하지 않았다.

| 운영 요청 | 결과 |
|---|---|
| 인증 헤더 없는 `GET /public-analytics/meta` | **401** `UNAUTHORIZED_NO_AUTH_HEADER`, 통계 필드 없음 |
| 형식이 잘못된 bearer JWT로 `GET /public-analytics/meta` | **401** `UNAUTHORIZED_INVALID_JWT_FORMAT`, 통계 필드 없음 |
| `https://safemap.worklazy.net`의 `OPTIONS /public-analytics/meta` | **204**, 지정 Origin 및 `authorization, apikey, accept` 허용 |

배포 후 네 사용자 전용 함수 각각에 무인증 요청을 다시 보냈다. `public-analytics/meta`,
`my-analytics/compare`, `community-ingest`, `community-account/status`는 모두 **401**
`UNAUTHORIZED_NO_AUTH_HEADER`였다. 로그인 전 중계인 `community-auth-relay`만 위 계약의 예외다.

실제 자격 있는 카카오 계정 200과 무자격 계정 403은 해당 사용자 세션이 없어 **NOT_RUN**이다.
이 결과는 무인증 차단의 운영 확인이며 로그인 후 자격 판단 전체의 운영 확인은 아니다.
Pages workflow는 익명 `meta` 401 사전 검사를 통과해야 배포한다. 플랫폼 JWT 검사에서 먼저
거부하면 오류는 `UNAUTHORIZED_NO_AUTH_HEADER`, 함수에서 거부하면 `auth_required`다.
