# Edge 함수 사용자 인증 점검 · 2026-09-27 23:02 KST

## 적용할 계약

지도 통계, 내 통계, 신고 업로드, 계정 API는 호출자의 유효한 Supabase 사용자 세션을 확인한다.
통계 지도는 추가로 카카오 신원·활성 공유 동의·지도에 올라간 본인 신고 1건 이상을 확인한다.
`community-auth-relay`는 PC·Docker의 **로그인 시작 전** 중계이므로 사용자 JWT 예외다. 요청별
일회용 비밀과 요청 상태를 확인하며, 세션 연결 완료(`/complete`)는 사용자 JWT도 검증한다.
브라우저 `OPTIONS` 사전 요청과 거절 오류 응답에는 통계·계정 자료를 담지 않는다.

## 운영 읽기 전용 확인

Supabase CLI `functions list`에서 다섯 함수 모두 ACTIVE. 무인증 HTTP 관측:

| 함수 | 플랫폼 `verify_jwt` | 무인증 요청 | 판정 |
|---|---:|---|---|
| `public-analytics` v4 | false | `GET /meta` → **200**, 버전·coverage 등 반환 | **FAIL: 운영 재배포 필요** |
| `my-analytics` v4 | true | `GET /compare` → 401 | PASS(무인증 차단) |
| `community-ingest` v2 | true | `POST {}` → 401 | PASS(무인증 차단) |
| `community-account` v3 | true | `POST /status` → 401 | PASS(무인증 차단) |
| `community-auth-relay` v2 | false | 형식 오류 `POST /requests {}` → 400 | 합의한 로그인 시작 예외; 성공 요청은 capability 검증 필요 |

`my-analytics`의 무인증 CORS `OPTIONS`는 204와 지정 Origin·Authorization 허용 헤더를 반환했다.
운영 `public-analytics`가 200인 직접 원인은 운영 설정값 또는 배포 코드 조합이며, secret 값은 읽지 않았다.
현재 저장소의 이전 코드는 `ANALYTICS_ACCESS=public`일 때 인증을 건너뛰도록 되어 있었다.

## 운영 반영 경계

이 후보는 **운영에 배포되지 않았다**. 이 레포의 `PROJECT_RULES.md`는 push·Edge 배포·Pages 배포에
별도 명시 승인을 요구한다. 승인 후 `public-analytics`만 인증 전용 합성 후보에서 배포하고,
운영 `functions list`의 `verify_jwt=true`, 무인증 `meta` 401, 브라우저 preflight 204,
실제 자격 있는 카카오 계정 200, 무자격 계정 403을 확인해야 한다.
Pages는 그 뒤 새 커밋으로 배포하며 익명 `meta` 401 사전 검사가 통과해야 한다. 플랫폼 JWT 검사에서
먼저 거부하면 오류는 `UNAUTHORIZED_NO_AUTH_HEADER`, 함수에서 거부하면 `auth_required`다.
