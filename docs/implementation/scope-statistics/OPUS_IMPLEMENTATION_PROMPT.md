## 0. 확정된 제품 결정

사용자의 요구는 다음을 하나의 흐름으로 구현하는 것이다.

1. 오른쪽 주소 상세를 전국·시도·시군구·현재 적용된 지도 범위까지 지원하는 **선택 범위 상세**로 확장한다.
2. 핀을 다시 누르거나 선택 해제·Esc·지도 빈 영역 클릭으로 해제할 수 있게 하고, 선택된 핀을 지도에서 명확하게 강조한다.
3. 사이드바 스크롤 이동이 실제 스티키 영역의 높이를 고려하게 한다.
4. 좌측 사이드바에 **통계**를 추가하고 별도 **맞춤 통계** 화면으로 이동하게 한다. 모바일 내비게이션에도 같은 진입점을 제공한다.
5. 맞춤 통계는 행·열·지표·필터·전체/내 신고를 사용자가 조합하는 피벗형 분석 화면이다.
6. **표 / 그래프** 전환 시 현재의 조합과 결과를 그대로 시각화한다. 자동 추천 차트와 수동 변경을 모두 지원한다.
7. 기관·담당자·지역·법규처럼 항목이 많은 차원은 **비교 대상 선택**에서 검색해 원하는 몇 개만 골라 구성할 수 있게 한다. 긴 셀렉트 하나로 수천 개 항목을 나열하지 않는다.

8. 메인 **월별 추이 → 처리결과 비율**은 수용률·불수용률·일부수용률·과태료처분율을 체크박스로 복수 선택해 같은 그래프에 겹친다. 표 보기·내 신고 비교·선택 보존까지 함께 연결한다.
9. 실제 조회·갱신 중임을 **상단 공통 상태 표시와 관련 패널 상태**로 즉시 인식할 수 있게 한다. 로딩 때문에 지도를 제거하거나 마지막 정상 화면을 지우지 않는다. 준비·조회·반영·재시도 대기·오류는 실제 상태에 맞춰 표시한다.

메뉴명은 `통계`, 화면 H1은 `맞춤 통계`, 진입 버튼은 `이 조건으로 통계 만들기`로 확정한다. 기존 고정 그래프 섹션의 `추이`는 유지한다. 새 `통계`를 기존 그래프 섹션으로 스크롤하는 버튼으로 만들면 안 된다.

추가 인터뷰를 전제로 멈추지 않는다. 아래의 기본 동작을 사용하고 충돌하는 기존 규칙이 있으면 최신 사용자 요구 범위에서 해결·기록한다.

## 1. 작업 범위와 회귀 방지

이번 작업은 지도 읽기·분석 UX의 확장과 월별 복수 비율·조회 상태 가시성 개선이다. PC/모바일 업로더, 신고 동의 범위, 공개 범위, 기존 레이아웃 전체를 임의로 바꾸지 않는다.

유지할 사항:
- 카카오/Supabase 로그인, 열람 자격 및 현재 동의 규칙.
- 원본 차량번호·신고번호·계정 식별정보 비공개, 차량번호 마스킹, 원문 보존.
- 신고 identity·최신 답변 대표 선택·계정별 소유권에 따른 중복 제거.
- 주소 기반 핀 묶기와 원본 좌표 보존.
- `신고 수`는 주소 핀, `수용률/불수용률/과태료`는 핀 없는 시도/시군구 색칠 지도.
- 장기간 조회, 실제 전체 기간 프리셋, 요청 중 마지막 정상 화면 유지. 유지된 값이 이전 조건이라는 안내와 S10의 로딩 표시는 함께 제공한다.
- 상세 필터 날짜 키보드 입력, 포커스 유지, 활성 필터 반전색.
- 주소 상세의 기관·담당자 지표 박스와 담당자 복합 차트.
- 내 신고 상태별 별점·과태료 처분 별점 분포, 1건 일반 표기.
- 지도에 이미 삭제한 `내 신고가 있는 곳/함께 신고한 곳/관심 지역` 탭과 `보이는 지역만 보기` 버튼을 되살리지 않는다.
- 표본 1건을 숨기거나 최소 표본 수를 새로 강제하지 않는다.

‘모든 업로드 컬럼 활용’은 **분석 가능한 정보는 분석에 사용하고, 비공개 정보는 내부 식별·파생 계산에만 사용한다**는 뜻이다. 업로드됐다는 이유만으로 원본 전체를 브라우저로 내려보내지 않는다.

## S01. 선택 범위 상세 패널

### 1.1 기본 동작

오른쪽은 핀이 선택되지 않았을 때도 비어 있지 않게 한다. 현재 실제 표시된 조건(`displayedScope`)의 상세를 보여준다.

| 상황 | 오른쪽 패널 |
|---|---|
| 전국, 추가 지역 필터 없음 | 전국 신고 현황 |
| 서울특별시 명시 선택 | 서울특별시 신고 현황 |
| 서울특별시 강서구 명시 선택 | 강서구 신고 현황 |
| 자동 지도 통계 갱신으로 bbox 적용 | 현재 지도 범위 / 특정 지역 × 지도 범위의 현황 |
| 주소 핀 선택 | 선택한 주소의 현황 |
| 핀 선택 해제 | 주소 선택 전부터 유지되는 최신 적용 범위 상세로 복귀 |

지역 귀속은 **신고 위치의 현재 행정경계** 기준이다. 처리기관의 소재지로 신고 지역을 대신하지 않는다. 주소 핀 표시용 대표 좌표로 모든 원본 신고의 행정구역을 재분류하지 않는다.

### 1.2 지역 진입점과 상위 이동

상단 컨트롤의 별도 지역 선택기, 행정구역 Polygon 클릭, 기존 지역 목록 클릭을 같은 지역 선택 액션으로 연결한다. `신고 수` 모드에서도 지역 상세를 볼 수 있어야 한다.

상단 지역 선택기는 `시도 [전체/서울특별시…] · 시군구 [전체/강서구…]` 형태로 두고 조건 변경 시 시군구 후보를 갱신한다. 실제 공식 코드와 경계 계층을 사용한다. 이름이 같은 지역을 병합하지 않는다.

패널에는 `전국 › 서울특별시 › 강서구 › 선택 주소` 경로를 제공한다. 상위 경로 클릭은 해당 지역으로 명시적으로 이동하는 액션이다. 단순 닫기와 구별한다. 주소의 행정경로와 실제 적용 조건이 다르면 ‘현재 조건’ 설명으로 구분하고, 해제 동작이 주소의 부모 지역 필터를 몰래 새로 걸지 않게 한다.

지역 선택 시 이전 주소 선택은 해제하고 기존 정책대로 이전 viewport 필터와 충돌을 정리한다. 명시적 지역 이동은 옛 bbox를 해제한 뒤 지역 전체를 보여주는 것을 기본으로 한다. 이후 자동 갱신 ON 상태의 실제 사용자 지도 이동은 지역∩bbox 조건으로 동작할 수 있다. `fitBounds`로 발생한 idle은 사용자 이동으로 오인하지 않는다.

### 1.3 내용과 레이아웃

기존 주소 카드와 지표 박스를 재사용해 동일한 시각 언어로 구성한다.

- 선택 범위명·기간·적용 조건·`이 조건으로 통계 만들기`.
- 신고/답변·계도·과태료·수용·일부수용·불수용 지표와 각 분모.
- 수용/일부수용/불수용 구성.
- 전국에서는 하위 시도, 시도에서는 하위 시군구 탐색 목록.
- 처리기관별 지표 박스 및 담당자별 지표 박스.
- 해당 범위의 담당자별 막대+건수 꺾은선 차트. 기존 수용률/과태료처분율 전환 유지.

안내/처리결과/기관담당자 탭을 다시 만들지 않는다. 긴 기관·담당자 목록에 검색·정렬·페이지/더 보기를 제공하고 내용량에 맞춰 배치한다. 넓은 표를 좁은 패널에 축소해 넣지 않는다. 상단에 이미 같은 KPI가 있으면 중복 긴 표를 또 붙이지 말고 상세 패널에서 정돈한다.

시도·전국에는 담당자가 많다. 첫 화면은 일정 개수 미리보기로 제공해도 되지만 ‘표시 N / 전체 M’과 실제 전체 조회가 있어야 한다. 요약 상위 배열만 검색하고 전체 검색처럼 표현하지 않는다. 총계·분모는 미리보기 개수와 무관하게 전체 적용 집합으로 계산한다.

### 1.4 상태와 데이터 배선

권장 분리(이름은 예시):

```ts
type InspectorSelection =
  | { kind: 'scope' }
  | { kind: 'place'; placeKey: string };

// 서로 다른 상태다.
// requestedScope: 사용자가 요청한 조건
// displayedScope: 실제 화면의 정상 snapshot 조건
// viewport: 지도 현재 위치/줌(항상 통계 필터는 아님)
// inspectorSelection: 범위 안의 일시적인 주소 선택
```

핀을 클릭했다고 전역 `scope`를 주소 bbox로 바꾸지 않는다. 범위 상세 API는 국가/지역/bbox 조건을 재사용하고, 주소 상세는 같은 조건+place_key로 범위를 좁힌다. 패널 header·기관목록·내 신고·차트가 동일 scope/version인지 검증한다.

`ScopeDetailsPanel`·공통 `EntityMetricRow`·`ScopeEntityChart`처럼 재사용 가능한 단위로 추출한다. 별도 `scope-detail` 읽기 endpoint 또는 기존 overview/entities API 조합 중 일관성과 중복 조회가 적은 방식을 선택한다. 새 endpoint를 만들면 client·public/personal DTO·Zod·fixture·테스트도 함께 연결한다. 주소별/지역별 내 신고는 검증된 로그인 사용자를 기준으로 서버 집계한다. 조회 중 범위 상세·기관목록·담당자 차트의 상태는 S10에 따라 각각 표시한다. 주소 A→B 변경 중 A의 값을 B 제목 아래에 그대로 붙이지 않는다.

## S02. 핀 선택·해제와 지도 강조

### 2.1 사용자 동작

1. 핀 A 첫 클릭 → A 선택·상세 열림.
2. 같은 핀 A 재클릭 → 선택 해제·기본 범위 상세 복귀.
3. 다른 핀 B 클릭 → B로 선택 교체.
4. 패널 상단 `선택 해제` 버튼 → 같은 해제 액션. 화면에서 잘 보여야 한다.
5. 지도 빈 공간 클릭 → 선택 해제. 단, 실제 지도 이동·마커·클러스터·지도 조작버튼·Polygon 선택과 구별한다.
6. Esc → 주소 선택 해제. 드로어/메뉴/통계 대상 선택창이 열려 있으면 최상위 UI부터 닫고 주소 선택까지 연쇄 해제하지 않는다. 입력 중 Esc를 무조건 가로채지 않는다.
7. 지역/기간/필터 변경 후 선택 주소가 새 결과에 없으면 주소 선택 해제. 새 조건을 설명하고 stale 결과를 남기지 않는다.
8. 비율 지도 모드로 변경 → 주소 선택 해제, 지도에는 지역 레이어만 유지.

중앙 `clearPlaceSelection(reason)`과 `togglePlaceSelection(key)` 액션으로 패널·지도·키보드·목록을 통합한다. 클릭 시 이미 선택된 키인지 최신 상태를 읽어 stale closure를 방지한다.

### 2.2 해제 후 무엇을 보여줄지

해제는 필터 초기화가 아니다. 날짜·분류·법규·기관 필터·지도 중심·줌을 보존한다.

- 명시적 지역 선택 있음: 그 지역의 현재 적용 조건 상세.
- 자동 지도 갱신 ON: 마지막 정상 적용 viewport 범위의 상세. 갱신 중이면 마지막 정상 조건을 표시한다.
- 자동 갱신 OFF + 명시적 지역 없음: 전국 등 현재 적용 범위 상세.
- OFF라도 과거 bbox가 남아 있으면 ‘마지막으로 적용한 지도 범위’임을 명시한다.

자동 갱신 OFF 상태에서 핀 해제만으로 몰래 현재 화면을 새로운 통계 필터로 적용하지 않는다. ‘화면에 보이는 지역과 연결’은 기존 자동 갱신 ON 기능과 결합한다. 이미 삭제한 viewport 적용 버튼을 재도입하지 않는다.

### 2.3 선택 강조

선택 상태는 hover·내 신고·관심 표식과 독립적으로 최우선 표시한다.

- 선택 핀 크기 약 1.2~1.3배(실제 겹침과 터치 영역을 보고 조정).
- 밝고 어두운 배경 모두에서 보이는 이중 halo/outline과 높은 z-index.
- ‘선택됨’ 작은 텍스트/주소 callout 또는 동등한 비색상 단서.
- 내부 신고 건수는 유지. 선택 때문에 metric 색상 의미를 바꾸지 않는다.
- 마커 이미지 크기가 달라지면 anchor/offset도 맞춘다.
- 애니메이션은 불필요한 지속 pulse를 피하고 reduced-motion을 존중한다.

`mark.mine` 테두리가 selected를 덮지 않게 SVG 우선순위를 바꾼다. 필요 시 `Marker.setZIndex`/선택 overlay를 공식 SDK 방식으로 사용한다. 클러스터에 선택 핀이 들어가면 ‘선택 포함’만 표시하거나 자동으로 선택을 설명하고, 확대 시 원래 주소 키로 연결한다. 선택 때문에 매 갱신마다 pan/fit을 반복하지 않는다.

지도 blank click과 marker click의 SDK 이벤트 순서를 확인해, 핀 클릭 직후 부모 이벤트로 해제되는 현상을 막는다. 공식 `preventMap` 등 적용 가능한 수단을 확인하되 임의 DOM 전파 처리가 Kakao 이벤트를 막는다고 가정하지 않는다. drag 후 synthetic click도 검증한다. 지도 빈 클릭 handler는 실제 뒷배경 클릭에서만 작동한다.

선택 해제로 주소 요청을 취소할 때 해당 요청의 로딩 상태도 정리하되, 동시에 진행되는 범위 조회·내 신고 조회는 종료시키지 않는다(S10).

마커/overlay/리스너는 제거 시 정리한다. hide만 해 놓은 오래된 선택 overlay나 비율 모드 원형 핀이 재등장하면 실패다.

## S03. 스티키 영역을 고려한 스크롤·내비게이션

### 3.1 측정

`useStickyInsets` 또는 동등한 공통 훅을 만들어 실제 상단 가림 높이를 계산한다.

- TopBar 및 실제로 화면 상단에 붙어 콘텐츠를 가리는 sticky/fixed 영역을 식별한다.
- ResizeObserver·viewport resize·필요 시 sticky 상태 변화를 관찰한다.
- 겹치는 영역을 무조건 높이 합으로 더하지 말고 실제 가려지는 연속 영역의 하단을 구한다.
- 모바일 접힘, 글꼴 로딩, 로그인 이름 길이, 확대/축소, 브리핑 모드 등을 반영한다.
- 아래쪽 모바일 내비게이션은 상단 offset에 더하지 않는다.

S10의 상단 조회 표시를 헤더 내부의 예약된 슬롯에 배치해 헤더 높이·문서 흐름이 매번 흔들리지 않게 한다. 별도 sticky 행을 실제 추가한다면 그 가림 높이도 여기의 측정 대상에 포함한다.

측정 결과는 `--scroll-top-inset` 같은 별도 읽기용 CSS 변수로 내보낸다. 측정한 값을 다시 `.topbar`의 높이를 결정하는 `--topbar-h`에 써서 ResizeObserver 루프를 만들지 않는다.

### 3.2 공통 이동 함수

모든 섹션 이동을 `scrollToSection(id, options)` 같은 공통 함수로 통합한다. 요소의 실제 scroll container 기준으로 목표 위치를 구하고, 상단 실제 가림 높이+약 12px 여유를 한 번만 뺀다.

네이티브 anchor/본문 바로가기는 `scroll-margin-top` 또는 `scroll-padding-top`으로 대응한다. JS offset과 CSS margin을 이중 적용해 여백을 두 번 빼지 않게 한다. 주 전략 하나를 정하고 테스트한다.

대상은 섹션 제목 전체가 보이는 위치다. 라우팅 후 이동은 실제 컴포넌트 mount와 레이아웃 측정이 끝난 후 수행한다. 고정 500ms setTimeout만으로 동작을 맞추지 않는다. 필요한 경우 requestAnimationFrame 기반의 제한된 1회 보정만 사용한다.

키보드 이동 시 제목에 `tabIndex=-1`, `focus({preventScroll:true})` 등을 적용해 사용자가 도착 지점을 인식하게 한다. reduced-motion에서는 즉시 이동한다.

### 3.3 사이드바

데스크톱/모바일 공통 항목: **지도 · 지역 · 기관 · 추이 · 통계**. 안내는 기존 접근성을 유지한다.

- 지도/지역/기관/추이: 메인 대시보드의 정확한 섹션으로 이동.
- 지역은 실제 지역 목록 anchor로 이동하며 `mapsection` 오지정을 정리한다.
- 통계: 별도 화면 이동.
- 통계 화면에서 지도/기관 등을 누르면 대시보드를 복원하고 해당 anchor로 이동.
- scrollspy/active 표시도 측정된 sticky inset을 기준으로 일치시킨다.
- 페이지 전환은 `aria-current=page`, 문서 내 섹션 활성은 용도에 맞는 상태로 구별한다.
- 뒤로/앞으로 이동은 목적 화면·스크롤 위치·조건을 복원한다.

## S04. 별도 맞춤 통계 화면·라우팅

### 4.1 구조와 접근

앱 공통 인증·TopBar·Rail·테마를 유지한 채 새 `StatisticsPage`를 추가한다. 기존 `view=stats`(대시보드 표시 방식)와 새 페이지 상태를 혼용하지 않는다.

GitHub Pages 정적 호스팅에서도 새 화면 직접 열기·새로고침이 가능해야 한다. 기존 프로젝트 구조에 맞는 실제 지원 라우팅을 사용한다. 별도 rewrite 없는 `/statistics` pathname을 만들고 새로고침 404를 방치하지 않는다. 가벼운 대안은 `?screen=statistics` / `?screen=dashboard`다. 기존 OAuth callback/fragment, scope query, base path와 충돌하지 않게 한다. 화면용 query가 API의 허용되지 않은 parameter로 전달되지 않게 adapter에서 분리한다.

지역·주소 상세, 기관×법규 차트 등에 `이 조건으로 통계 만들기`를 둔다. 현재 실제 표시 조건을 넘기며 요청 중 새 조건과 혼합하지 않는다. 주소 선택이면 같은 place_key 범위를 명시적으로 넘긴다. 새 페이지에서 주소 조건을 해제할 수 있게 chip으로 보여준다.

통계에서 지도 돌아오기는 기존 범위·지도 중심·줌·필터를 복원한다. 화면 전환 자체와 무관한 scope 갱신에서 지도 인스턴스를 재생성하지 않는다. 페이지 이탈 시 지도 유지/파기 방식은 자원 관리에 맞춰 정하되 복귀 상태가 복원되고 숨겨진 지도 요청이 계속 돌지 않아야 한다.

### 4.2 레이아웃

H1 `맞춤 통계`, 부제 `행·열·지표와 비교할 대상을 골라 표와 그래프로 확인합니다`.

데스크톱:
- 좌측 또는 접을 수 있는 약 280~320px 설정 패널.
- 설정은 대상 범위/필터, 행, 열, 지표, 비교 대상 선택 순으로 구성.
- 오른쪽 넓은 결과 영역: 조건 요약·실행 상태·`표/그래프`·차트 유형·주 지표·저장.
- 드래그만 강요하지 말고 추가/삭제/순서 이동 버튼과 키보드 조작을 지원.

태블릿/모바일은 설정을 위 또는 드로어로 바꾸고 결과 영역을 확보한다. 너무 넓은 교차표의 가로 스크롤은 결과 카드 안에만 둔다. 고정 첫 열·헤더는 앱 스티키바 아래에서 가리지 않게 한다.

초기 프리셋은 ‘기관 × 위반법규 / 과태료처분율’로 하되, 인계받은 필터와 대상 선택은 보존한다. 기관 없이 특정 담당자에서 진입하면 해당 조건에 맞는 축으로 보정하되 조용히 scope를 삭제하지 않는다. 프리셋에는 기본 예시 5~6개를 제공하고 사용자가 수정할 수 있게 한다. 이탈/복귀 시 작성 중 설정과 마지막 적용 결과를 보존한다. `통계 만들기`를 누른 후에는 S10의 실행 중 상태를 결과 헤더에 표시하고, 전 결과를 유지할 때는 이전 적용 조건을 분명히 적는다.

## S05. 필드 카탈로그와 피벗 집계

### 5.1 전체 필드 감사

다음 실제 업로드 필드를 빠뜨리지 말고 ‘원천 → 저장/파생 → 허용 용도 → 공개 여부 → 결측’ 표를 문서화한다. 아래는 계약 확인 기준이며 기존 projection을 재검증한다.

| 원천 | 분석 화면에서의 처리 |
|---|---|
| `report_date`, `completed_date` | 각각 연/분기/월/일/요일 파생, 범위 필터. 기본 조회 기간 기준은 답변 완료일 |
| `category` | 교통위반/주정차/기타 그룹·필터 |
| `status` | 수용/일부수용/불수용/결과 미상 그룹·필터. 완료 자료 모집단 규칙 유지 |
| `status_raw` | 원상태 구분. 기존 public fact에 없다면 event/journal로부터 서버 projection 가능한지 확인, 새 공개 허용으로 임의 간주하지 않음 |
| `disposition` | 과태료/계도/범칙금/해당 없음/미확인 그룹·필터 |
| `amount.kind` | 금액종류 구분. 기존 공개 projection이 허용하는 의미만 노출 |
| `amount.confirmed_won` | 공개 동의된 확인 금액의 집계·명시한 구간. 추정 금액·미확인 0원 금지 |
| `amount.penalty_points` | 현재 비공개 저장 항목. 이번 통계 UI/API에 임의 노출 금지 |
| `address` | 정규화 장소 키/주소 그룹·주소 범위. 실제 공개 허용 주소 사용 |
| `location.lat/lng` | 신고 위치 지역 귀속·bbox·공간 필터 내부 계산. 위도 합계 같은 무의미한 지표를 제공하지 않음 |
| `location.source` | 좌표 유무/위치자료 상태. 기술 필드를 그대로 노출하기보다 의미 있는 품질 항목으로 제공 |
| `vehicle_raw` | 서버 내부 정규화·distinct 차량 수·반복 신고 집계. 원번호/지속 차량 키의 날짜·주소 추적용 축 노출 금지 |
| `agency_name` | 당시 기관명. 현재 이름과 구분 |
| `source_agency_code` | 서버 기관 식별·현행명/기관 유형 파생. raw code 공개 허용 여부를 기존 정책에서 확인 |
| `manager_name` | 기관+담당자 식별로 그룹. 이름 단독으로 타 기관 동명이인 병합 금지 |
| `violation_law` | 허용된 법 이름·조 단위 그룹/필터. private 항 원문 전체를 신규 노출하지 않음 |
| `rating` | 공개 동의된 1~5점 그룹/분포·평균·평가 건수 |
| `source_report_id`, `report_number` | private 신고 identity·중복 제거용. 공개 원문 열로 사용하지 않음 |
| 계정/연결/이벤트/해시/정책·앱 버전/수신 시각 | 내부 권한·동기화·출처 검증용. 일반 사용자 분석 차원으로 노출하지 않음 |

존재하지 않는 신고제목·발생일시·신고본문·처리답변 원문·별점사유·첨부는 생성하지 않는다. 신고요일과 위반발생요일을 혼동하지 않는다.

지원되는 공개 의미 필드는 초기 구현에서 활용 가능하게 배선하고, 일부만 하드코딩한 3개 preset을 ‘맞춤 통계’라 하지 않는다. 다만 공개 제한 또는 실제 미수집 항목은 이유를 기록하고 값·권한을 지어내지 않는다. 일반 UI에는 수십 개 private 기술필드를 회색으로 나열하지 않는다.

### 5.2 Registry

서버를 정본으로 한 field/metric registry를 두고 프론트 필드 선택기도 이를 따른다.

각 항목에는 id, 한글 label, type, allowedRoles(row/column/filter/metric/internal), allowedOperators, granularity/bins, allowedAggregations, unit, nullPolicy, eligibility/permission, description을 정의한다. 반환 DTO는 사용자가 고를 수 있는 공개 항목만 포함한다. DB 테이블/열 이름·SQL 조각·실행식을 사용자로부터 받지 않는다.

기본 차원:
- 시도, 시군구, 주소, 당시/현행 기관, 기관 유형, 담당자.
- 법규, 신고분류, 처리결과, 처분종류.
- 신고일/답변일의 연·분기·월·일·요일.
- 별점, 처리기간 구간, 공개 확인금액 구간, 자료 확인 여부.

행과 열은 복수 차원을 지원한다(초기 권장 행 최대 3·열 최대 2). 지표도 복수 선택 가능(초기 권장 최대 6). 한계는 서버 budget에 따라 명시하고 무제한 쿼리를 허용하지 않는다. 특정 값이 1건이라는 이유로 막는 제한과 처리량 제한을 혼동하지 않는다.

### 5.3 지표와 분모

C=해당 cell의 답변 완료 수, A/P/R=수용/일부/불수용, K=A+P+R, F=과태료, W=경고·계도, B=범칙금.

- 답변 건수, 수용/일부/불수용 건수, 결과 미상 건수, F/W/B 건수.
- 수용/일부/불수용률=A/K, P/K, R/K.
- 과태료/계도/범칙금 처분율=F/C, W/C, B/C.
- 확인된 과태료 금액 합계·평균·중앙값·금액 확인 건수/커버리지. 범칙금·혼합금액을 과태료 합계에 합치지 않음.
- 처리기간 평균·중앙값·P90·계산 가능 건수. 역전/결측 제외 규칙 재사용.
- 평균 별점·평가 건수·1~5점 건수/비율·평가 커버리지.
- 식별 가능한 차량 수·주소 수 등 distinct 지표. 범위·집계 가능 정책을 확인.
- 전체/내 신고/나란히 비교. 내 신고는 verified viewer에서만 파생.

기본 `dateBasis=completed_date`. 신고일 기준도 제공한다면 명시적 선택으로 두고 두 기준의 모집단과 날짜 누락 처리를 정의한다. 조회 기준과 행/열 날짜 granularity는 다르다. ‘답변월로 기간 제한하고 신고월로 그룹’이면 그대로 표시하고 조용히 날짜 기준을 바꾸지 않는다. 범용 `선택 신고 건수`와 `답변 건수`를 같은 이름으로 섞지 않는다.

고정 의미의 수용률과 `행 내 비율/열 내 비율/전체 비율`은 별도 지표다. 상태=수용만 필터한 수용률이 100%인 것은 조건부 값이며 별도 보정하지 않는다. 항목 고르기로 모집단을 좁혔다면 분모도 현재 조건 기준이라는 설명을 표시한다.

합계·소계는 원천에서 재계산한다. 비율 평균, 중앙값 평균, 평균의 단순 평균, distinct 건수의 단순 합을 금지한다. unknown은 0이 아니다. 중첩 계층(시도와 시군구) 소계를 중복 더하지 않는다. 전체+내 신고는 겹치는 집합이지 합산 partition이 아니다. 상태와 과태료 처분도 서로 다른 축이다.

### 5.4 결과 모델과 조회

`StatisticsQuery`는 typed declarative 구조다. 예시(실제 내부 이름은 registry에 맞춘다):

```ts
interface StatisticsQuery {
  version: 1;
  scope: { start: string; end: string; dateBasis: 'completed_date' | 'report_date';
    regionCode?: string; bbox?: [number,number,number,number]; placeKey?: string };
  population: 'all' | 'mine' | 'compare';
  rows: DimensionSelection[];
  columns: DimensionSelection[];
  metrics: string[];
  filters: AllowedFilter[];
  order: AllowedOrder[];
  page: { cursor?: string; size: number };
  expectedDatasetVersion?: string;
}
```

`queryKey`와 결과 metadata에는 적용 query·기간기준·권한 관점·dataset_version·제외수·complete/truncated 상태를 포함한다. 페이지/표현 설정을 제외한 데이터 query identity와 chart 표현 identity를 분리한다.

결과는 row/column member key+label, metricId, value, numerator, denominator, eligibleCount, missingReason, totals, coverage, resultId/version 형태의 정규 집계 데이터다. raw 신고 배열·private id는 반환하지 않는다.

서버에서 필터 → 기존 권한·canonical 규칙에 맞는 사실 선택 → 실제 교차 집계 → 전체 정렬 → 페이지 처리를 수행한다. 대표 선택과 필터 적용 순서 때문에 신고 정체성이 바뀌지 않도록 기존 규칙을 따른다. 기존 dashboard top100 배열·마스킹된 차량번호를 원천으로 집계하지 않는다.

## S06. 비교 대상 선택 — 기관·담당자 몇 개만 고르기

이 기능은 작은 보조 셀렉트가 아니라 **독립적으로 열 수 있는 비교 대상 선택 Drawer/Dialog**로 구현한다. 새 앱 메뉴를 또 만들 필요는 없고 맞춤 통계 설정과 결과 도구줄의 `비교 대상 선택`에서 접근한다. 주소/지역 상세에서도 담당자 비교 진입으로 재사용할 수 있다.

### 6.1 UI

예시: `행: 기관 [전체 ▼] [대상 선택]` → 검색 후 기관 A·B·C 체크 → 선택된 3곳 확인 → 적용.

- 기관/담당자/지역/법규 대상 종류 선택.
- 검색창, 기관유형 필터, 필요 시 소속기관 필터.
- 서버 페이지 후보 목록과 체크박스.
- 별도 ‘선택한 항목 N개’ 영역: 칩 삭제, 전체 해제, 선택만 보기, 순서 변경.
- 검색 결과 페이지가 바뀌어도 선택 유지.
- ‘이 페이지 선택’과 ‘모든 결과 선택’을 혼동시키지 않는다. 무제한 검색 전체 선택은 제공하지 않아도 된다.
- 닫기/취소는 선택 초안만 폐기. 적용 후에만 실제 query를 변경.
- 긴 드롭다운이나 모든 담당자 다운로드를 피한다.
- 첫 사용에는 2~10개 비교를 안내할 수 있지만 1개도 정상 지원한다. 표본수와 대상 개수를 혼동하지 않는다.

분류가 바뀌어도 사용자 선택이 조용히 삭제되지 않는다. 현재 조건에서 0건인 선택 대상은 ‘현재 조건 0건’으로 남겨서 사용자가 제거하게 한다. 권한/정책상 더 이상 사용할 수 없는 대상은 0건 대신 이용 불가로 분리한다. 조용히 ‘전체’로 바꾸지 않는다.

### 6.2 후보 조회·식별

`candidates(kind, search, scope, cursor, limit)`처럼 서버 검색 API를 둔다. 실제 전체 후보 집합을 검색하고 summary 배열만 검색하지 않는다. 250~350ms debounce, AbortController, 응답 순서 검증, 안정 cursor/key를 사용한다. 한글 IME 조합 중에는 조기 검색/포커스 이동을 하지 않는다. 후보 조회 중에는 후보 목록 영역에만 검색 중 상태를 표시하고, 선택한 항목 목록은 보존한다. 상단 상태는 후보 조회와 본통계 조회를 구별한다(S10).

후보 scope는 기간·지역·법규 등 다른 필터를 반영하되 **자기 차원의 기존 선택만으로 후보가 막히지 않게** 한다. 예: 기관 A 선택 후 다시 대상창을 열어도 B를 추가할 수 있어야 한다. facet 규칙을 문서화한다.

기관은 기관키, 담당자는 기관키+담당자키(필요한 경우 구조화된 복합키)를 사용한다. 기관 A의 김OO와 기관 B의 김OO는 별도 후보로 보이고 합쳐지지 않는다. 같은 기관 내 동일 이름을 실제 동일 인물이라고 확정할 식별값이 없으면 ‘기관·성명 기준’임을 유지한다.

같은 차원의 복수 선택은 OR, 서로 다른 차원 필터는 AND가 기본이다. 여러 소속기관의 담당자 선택은 `(기관A AND 담당자X) OR (기관B AND 담당자Y)`의 복합 식별 union으로 처리하고 잘못된 cross-product로 해석하지 않는다.

### 6.3 분석대상 선택과 범례 숨김 구별

선택한 기관/담당자는 **서버 query의 모집단 필터**이며 표·차트·소계·내 신고 비교 모두에 적용한다. 차트에서만 시리즈를 숨겨놓고 전체를 같은 것으로 부르지 않는다.

차트 범례 클릭의 단순 시리즈 숨김은 표현 동작이다. 이 동작으로 집계 분모/총계/필터를 몰래 다시 계산하지 않는다. `분석 대상 3개 · 화면에 표시 2개`처럼 차이를 구별한다.

예시 시나리오를 완성한다: 서울 강서구 조건 → 기관 A/B/C 선택 → 행 기관, 열 답변월, 지표 과태료처분율 → 그래프 전환 → 3개 기관 선 → B 제외 후 적용 → 표/그래프/합계가 같은 두 기관 조건으로 변경.

## S07. 표 ↔ 그래프 전환·자동 차트

### 7.1 핵심 계약

`표/그래프`는 같은 `StatisticsResult`를 표현하는 두 renderer다. 그래프 버튼은 고정 preset을 새로 만드는 것이 아니라 **현재 행·열·지표·필터·비교대상·정렬의 결과**를 차트로 표현한다. 전환 후 다시 표로 돌아와도 설정을 보존한다.

레이블·축·tooltip·제목·분모 설명은 registry와 결과 metadata에서 만든다. 일반 원본 열 순서에 의존하지 말고 field/member key와 metricId로 encode한다. 멀티지표 중 차트 주 지표를 선택 가능하게 한다.

결과가 메모리에 완전하게 있으면 표현 전환만으로 재조회하지 않는다. 표 페이지 데이터만 로드한 경우 그래프가 현재 20행만 전체인 것처럼 보여주면 안 된다. 같은 query/version의 선택 대상 전체 series를 별도 집계 response 또는 result fetch로 가져온다. 이 추가 fetch는 전체 cohort를 바꾸는 재조회가 아니다. 한도가 넘으면 명시적 대상 선택/Top N 설정을 제안하고 조용히 생략하지 않는다. 그래프 전환을 위해 추가 시리즈를 실제 가져오는 경우에는 결과 영역에 `그래프 데이터를 불러오는 중`을 표시한다. 로컬 표현 전환뿐인 경우에는 가짜 DB 조회 표시를 만들지 않는다(S10).

### 7.2 차트 자동 추천과 수동 선택

| 데이터 모양 | 기본 제안 |
|---|---|
| 범주 하나+지표 하나 | 막대, 기관/담당자 긴 이름은 가로 막대 |
| 시간축+지표 | 꺾은선; 다른 축에 선택한 기관이 있으면 기관별 시리즈 |
| 범주×범주+지표 | 히트맵, 0~100% 지표는 고정 스케일 |
| 한 집합을 상호배타 범주로 나눈 건수 | 묶은/누적 막대; 명시한 분모로 100% 누적 가능 |
| 같은 관측단위의 수치 지표 두 개 | 산점도; 예: 기관별 중앙처리기간×과태료처분율 |
| 별점/처리기간/확인금액 구간+빈도 | 분포 막대. 실제 구간집계가 있을 때만 히스토그램 의미로 사용 |
| 차원 없는 단일 수치 | 요약값+표. 의미 없는 선/원형 차트를 강제하지 않음 |

사용자는 `자동/막대/꺾은선/누적막대/100%누적/히트맵/산점도` 중 호환 가능한 유형을 선택한다. 모든 조합에 모든 유형을 허용하지 않는다. 호환되지 않는 조합은 이유를 표시하고 설정을 임의 변경하지 않는다.

- 행/열 중 하나가 날짜이면 표현상 날짜를 가로축에 배치할 수 있다. 원래 피벗 축을 바꾸지 않고 mapping 설명을 제공한다.
- 여러 행/열 차원을 차트가 표현하지 못하면 사용할 축·하위 항목을 사용자가 고르게 한다. 몰래 차원을 합치지 않는다.
- 멀티지표의 원·일·건·%를 한 축에 섞지 않는다. 기본은 ‘주 지표’ 선택. 선택적 복합축은 단위 표시와 사용자 선택이 있을 때만.
- 수용률을 여러 기관 간 더해 100% 누적으로 만들지 않는다.
- 수용/일부/불수용=K 기준의 partition, 과태료/그 외=C 기준의 partition을 구별한다.
- 수용과 과태료, 전체와 내 신고는 겹치는 집합이므로 서로 더해 하나의 100% 막대를 만들지 않는다.
- 범례 일부 숨김 때문에 분모를 다시 100%로 정규화하지 않는다.
- 날짜는 실제 날짜순; 기관명 축을 추세처럼 곡선 보간하지 않는다.
- 자료 없음은 0이 아니며 선을 연결하지 않는다. 실제 0값은 표시한다.
- 금액·별점 비공개/미확인을 0으로 넣지 않는다.
- 상위 N 표시가 필요하면 N·정렬 기준·전체 대비 표시범위가 사용자의 명시 설정이어야 한다. 내부 top100 한계를 그대로 누락으로 숨기지 않는다.

### 7.3 상호작용·상태

차트 cell/막대 선택은 해당 차원의 조건을 확인하는 작은 팝오버와 `이 항목으로 좁히기`를 제공한다. 잘못 클릭해 필터가 무조건 바뀌지 않게 한다. 실행하면 필터 chip을 추가하고 새 query/version으로 표·차트를 갱신한다. 기간만 바뀌어도 이전 row index가 다른 기관을 가리키지 않도록 key로 선택한다.

ECharts는 `src/lib/charts.ts`와 테마 토큰을 재사용한다. dataset/encode 또는 동등한 typed adapter로 공통 결과를 mapping한다. 필요한 DatasetComponent/LegendComponent/DataZoom 등은 실제 설치 버전과 모듈 사용에 맞춰 등록한다. 입력 텍스트·tooltip에 raw HTML을 무검증 삽입하지 않는다.

표 전환으로 hidden 컨테이너가 0px가 된 뒤 그래프로 돌아올 때 resize/init 상태를 처리한다. 그래프 전환마다 리스너·인스턴스가 누적되지 않는다. 주요 수치를 읽을 수 있는 표/접근성 텍스트 대안을 유지한다. 같은 member key는 차트 전환/정렬 후에도 같은 색을 유지하되 수용·불수용 등의 의미 색은 기존 토큰을 따른다.

## S08. 실행·보안·성능·구성 저장

### 8.1 공통 집계 경로

후보 경로 예시(새 경로이며 실제 현재 경로와 구별):

```
StatisticsPage / ScopeDetailsPanel
  → typed client + validated query
  → viewer-authenticated Edge handler
  → field/metric registry validation
  → authorized canonical facts / DB aggregate
  → exact grouped result + metadata
  → Zod response validation
  → PivotTable / PivotChart / Scope details
```

`statistics/catalog`, `statistics/candidates`, `statistics/query`처럼 구성할 수 있다. SQL/RPC는 private 원천을 서버에서만 읽는다. 임의 SQL·SQL 표현식·테이블명·DB 컬럼명이 들어오면 거부한다. 필드·연산자·정렬·그룹 개수·대상 개수·bin 개수·문자열 길이·기간·cell budget을 allowlist로 검증한다.

`mine`에 사용할 user_id는 JWT 검증에서 결정한다. 요청의 user_id를 신뢰하지 않는다. 새로운 endpoint도 동일 열람 자격·동의 철회·정책 projection을 검사한다. 후보 검색이 본조회보다 private 이름/대상 존재를 더 많이 노출하지 않도록 한다.

### 8.2 일관성·부하

오래된 요청 취소, 최신 응답 우선, debounce, 세션 변경 시 캐시 폐기, 429 Retry-After와 제한된 재시도를 적용한다. 캐시 키는 실제 viewer/session·scope·선택멤버·query·dataset version·정책 조건을 구분한다. 표시이름만으로 사용자 캐시를 구분하지 않는다. 토큰/원번호는 로그·공유 URL에 넣지 않는다.

한 쿼리에서 summary·cell·내 신고·totals를 같은 snapshot으로 계산한다. 문자열 dataset_version이 같다는 주장만으로 snapshot 일관성이 보장된다고 가정하지 않는다. 트랜잭션 또는 서버의 version fence/완료 시 재검증을 사용하고 변경 중이면 명확한 409로 처리한다.

장기간/전국 요청은 DB 필터·집계·인덱스 또는 일관된 batch 경로로 최적화한다. 원천 LIMIT 이후 일부 결과를 전체 결과로 보고하지 않는다. 결과 크기 제한은 사용자에게 조건 축소/대상 선택을 안내하되 표본 1건을 숨기는 정책은 만들지 않는다. 평균/중앙값/차량 distinct를 배치 부분 평균으로 병합하지 않는다.

화면 설정 draft는 선택 때마다 반응하지만 기본 데이터 실행은 `통계 만들기/적용` 클릭 시 1회다. 표현 변경은 로컬 처리. 후보 검색과 본조회 controller를 분리해 한쪽 취소가 다른 쪽을 잘못 죽이지 않게 한다. S10의 공통 상태 집계는 이 controller들의 상태를 읽을 뿐, 표시 컴포넌트가 네트워크 재시도를 새로 일으키면 안 된다.

### 8.3 저장·공유

‘구성 저장’은 브라우저에 이름+행/열/지표/허용된 선택대상/필터/차트 설정을 저장하는 것으로 구현할 수 있다. 결과 raw cache나 계정 토큰을 저장하지 않는다. 민감한 주소 선택·개인 컨텍스트는 viewer-scoped session에서 보존하고 공용 링크에 자동 포함하지 않는다.

처음 버전부터 브라우저 뒤로/앞으로·페이지 왕복·새로고침에서 허용된 설정을 복원한다. 서버 저장 테이블은 필수가 아니다. 공유 링크는 정책상 허용된 조건과 recipe만 포함하고 다른 사용자가 열면 자기 권한으로 재조회한다. `내 신고`가 작성자의 신원/원문을 전송하는 기능이 되면 안 된다. 길어진 선택목록은 무작정 URL로 붙이지 말고 로컬 구성으로 저장하거나 지원되는 별도 안전한 방식을 사용한다. 복원이 불완전하면 알리고 전체로 조용히 바꾸지 않는다.

CSV 내보내기를 구현한다면 사용자가 명시적으로 실행한 집계 결과만 대상으로 하며 현재 페이지/전체 범위를 명확히 한다. 한글 인코딩·쉼표·따옴표·줄바꿈과 수식 인젝션을 방어한다. CSV 기능 때문에 보안/정확성 검증을 생략하지 않는다. CSV는 이 작업의 필수 핵심은 아니다.

## S09. 월별 처리결과 비율 — 체크박스 복수 선택·겹쳐 보기

### 9.1 수정 대상과 사용자 조작

사용자가 첨부한 월별 추이 화면의 `건수 / 처리결과 비율` 구분은 유지한다. **처리결과 비율의 단일 select만 체크박스 기반 복수 선택으로 교체**한다. 지도 지표 버튼, 주소 담당자 차트의 라디오 버튼까지 복수 선택으로 바꾸라는 뜻은 아니다.

항목은 다음 네 가지다. 내부 기존 key와 표시 label을 분리하되 의미를 바꾸지 않는다.

| 내부 key 예시 | 화면 라벨 | 계산 |
|---|---|---|
| `accept` | 수용률 | 월의 A/K × 100 |
| `reject` | 불수용률 | 월의 R/K × 100 |
| `partial` | 일부수용률 | 월의 P/K × 100 |
| `fine` | 과태료처분율 | 월의 F/C × 100 |

배치 예시: `표시할 지표  [✓ 수용률] [□ 불수용률] [✓ 일부수용률] [✓ 과태료처분율]`.

- 네 항목을 독립적으로 체크할 수 있고 1~4개를 동시에 그린다. 체크박스처럼 보이는 단일 선택 라디오를 만들지 않는다.
- native checkbox+label 또는 동등한 접근성 있는 checkbox chip을 쓴다. checked 상태, 색상 표식, 라벨, 키보드 Space 조작을 지원한다.
- `전체 선택 / 전체 해제`를 제공한다. 모두 해제해도 임의로 수용률을 재선택하지 않고, 축·컨트롤·현재 조건을 유지하며 `비교할 지표를 선택해 주세요`를 표시한다. 이를 로딩이나 조회 실패로 취급하지 않는다.
- 새 사용자 기본값은 기존 동작을 존중해 수용률 1개다. 이전 단일 지표 preference가 있으면 해당 1개 배열로 이관한다. 사용자가 복수 선택하면 이후 그대로 유지한다.
- 기존 건수 모드의 신고/답변·내 신고 그래프와 데이터 기준은 유지한다.
- `건수↔비율`, `표↔그래프`, 필터·기간·지역 변경, 페이지 왕복, 테마 변경으로 체크 상태가 초기화되지 않는다. 기존 레시피/뷰 설정 저장 규칙과 함께 보존한다. 비공개 집계 결과나 토큰을 저장하지 않는다.
- 선택은 표현 상태다. 이미 받은 월별 데이터가 충분한데 체크할 때마다 API/DB를 다시 조회하지 않는다. 선택을 URL에 넣더라도 화면용 설정과 분석 scope를 분리한다.

### 9.2 시리즈·색상·전체/내 신고

선택 지표별 선을 **동일 0~100% 축에 겹쳐** 그린다. 누적 꺾은선·누적 면적으로 만들지 않는다. 과태료는 처리상태와 겹치고 분모도 다르므로 네 선의 합이 100%라는 설명을 붙이지 않는다.

색은 `--accepted / --rejected / --partial / --fine` 등 기존 의미별 토큰에서 읽는다. 선택 순서·정렬·테마 전환 때문에 지표의 색상 정체성이 뒤바뀌지 않게 한다. 라이트/다크 모두 선·체크 라벨·tooltip 대비를 실제 확인한다. 체크한 지표가 4개면 이름과 색을 모두 쉽게 확인할 수 있어야 한다.

- 전체는 실선·기본 마커, 내 신고는 같은 지표 색의 점선·다른 마커로 구분한다.
- `내 신고와 비교` ON이면 선택한 지표 각각의 전체/내 시리즈를 함께 표시한다. 네 지표라면 최대 8개 선이다. 임의로 2개만 표시하지 않는다.
- label 예: `수용률 · 전체`, `수용률 · 내 신고`. series id 예: `rate:accept:all`, `rate:accept:mine`. 배열 인덱스로 식별하지 않는다.
- 비교 OFF면 내 신고 선·마커·범례·tooltip·표 열을 모두 없앤다. 지표 체크 상태는 유지한다.
- 두 집단 값이 같으면 같다는 tooltip을 보여주고 offset/jitter로 수치를 왜곡하지 않는다. dash·symbol 차이는 유지한다.
- 내 신고 로딩/오류/권한 만료/지원 안 됨/분모 0을 구별한다. 아직 안 왔다고 전체 값을 내 값으로 복사하지 않는다. 전체 데이터만 먼저 유효하면 전체 선은 보여주고 내 비교만 로딩 표시한다(S10).
- checkbox가 ‘선택됨’인데 범례 클릭 때문에 선이 숨은 상태가 되지 않게 한다. 기본은 지표 checkbox가 해당 지표의 전체/내 선 모두를 제어하고 범례는 읽기 전용으로 둔다. 인터랙티브 범례를 유지한다면 동일 선택 상태로 양방향 동기화하고 의미를 명시한다.
- 여러 선을 읽기 위해 hover/focus한 선을 강조할 수 있지만, 비강조 선·툴팁 값을 바꾸지 않는다. 좁은 화면은 checkbox를 두 줄로 배치하고 차트 영역을 과도하게 줄이지 않는다.

### 9.3 날짜·분모·결측

현재 `monthRate()` 또는 공통 rate registry를 재사용한다. 답변을 받은 달의 실제 분자/분모로 계산하고 기관별 평균·기간 전체 비율을 월별로 배분하지 않는다. 내 신고는 그 달의 내 분자/분모다.

1. 수용/일부수용/불수용은 각각 A/K, P/K, R/K다. 결과 미상은 K에서 제외한다.
2. 과태료는 F/C다. 같은 달에 K=0이어도 C>0이고 F가 확인되면 과태료 비율은 그릴 수 있다.
3. 과태료 값이 없거나 내 outcome 필드가 없다는 이유로 **다른 지원 지표까지 통째로 막지 않는다**. 기존의 `mine_outcomes !== undefined` 같은 일괄 지원 여부 판정에 fine을 종속시키지 않는다. 지표별 필요한 필드로 판정한다.
4. 분모 0·필드 미지원·자료 부재는 `null`+이유다. 실제 분자 0/분모 양수는 정상 0%다. `value || 0`, `Number(null)`, null을 0으로 만드는 포맷 변환을 금지한다.
5. 모든 월·시리즈를 `YYYY-MM` key로 정렬·정합하고 누락한 달은 null gap으로 둔다. 배열 길이·index만 맞춰 내 신고를 다른 달에 대응시키지 않는다.
6. `connectNulls=false`, 기본 `smooth=false`. 자료 없는 구간을 이어 그리거나 과거 월을 0%라고 채우지 않는다. 반올림은 표시에서만 한다.
7. 진행 중인 달은 배지/tooltip으로 알리고 해당 월 값을 숨기지는 않는다. 과거 전체 기간을 선택한 경우에도 실제 마지막 월이 진행 중인 때만 배지를 표시한다.

### 9.4 Tooltip·표·맞춤 통계 인계

같은 월에 선택한 모든 지표의 값을 보여주는 축 tooltip을 사용한다. 지표별로 전체·내 신고 순서를 고정하고 `66.7% (12/18건)`처럼 분자/분모를 함께 표시한다. 분모가 없는 지표도 빠뜨리지 말고 ‘분모 없음/자료 없음’으로 표시한다. 실제 화면에 없는 내 데이터를 tooltip에 섞지 않는다.

비율 모드의 표도 선택 지표를 따른다. 예: `월 | 수용률 전체 | 수용률 내 신고 | 과태료처분율 전체 | 과태료처분율 내 신고`. tooltip·표·선은 같은 selector 결과를 사용한다. 기존 건수·금액·별점 표 정보는 건수 모드/상세 열에서 유지해 기능을 삭제하지 않는다.

`이 조건으로 통계 만들기`를 월별 카드에 제공하거나 이미 있다면 인계를 확장한다. 기간·지역·법규·모집단과 **선택한 복수 metricId**, 답변월 차원을 새 맞춤 통계 레시피로 넘긴다. 월별 전용 key를 서버 registry의 metricId로 명시적으로 매핑한다. 이전에 검증한 `StatisticsQuery`를 재사용하고 카드 UI 문자열을 SQL/DB 컬럼명으로 쓰지 않는다.

이 복수 비율 레시피는 맞춤 통계에서도 같은 단위인 여러 비율을 겹쳐 볼 수 있게 한다. S07의 ‘다른 단위를 한 축에 혼합 금지’는 유지하되, 같은 % 지표의 명시적 복수 표시까지 단일 주 지표로 강제하지 않는다. 선택 대상 N개×지표4개×전체/내2개로 선이 많아지는 경우 표시할 지표·집단·대상을 사용자가 고르게 하고, 한도 초과를 알리지 않은 채 시리즈를 버리지 않는다.

### 9.5 구현 배선

기존 경로: `server/aggregate.ts`의 monthly / `server/compare.ts`의 내 월별 분자·분모 → domain/schema/client → `TrendCard` → `useEChart`.

권장 분리(신규 이름 예시): `trendMetrics.ts`(정의·selector·series mapping), `MonthlyRateSelector`(checkbox), `TrendCard`(배치·표/그래프). `selectedRateMetrics`는 canonical 배열 또는 Set으로 관리하고 selector는 순수 함수로 테스트한다.

현재 `useEChart`는 차트 lifetime과 setOption 갱신을 분리한다. 이를 유지하고 checkbox 클릭마다 dispose/init하지 않는다. 안정 id와 기존 `notMerge:true` 또는 설치 버전의 검증된 series 교체 방식을 사용해 해제한 선이 남지 않게 한다. 지표 변경·표 보기 전환에도 리스너가 누적되지 않게 한다.

상세 수치가 이미 월별 DTO에 있으면 추가 업로드·새 원문 다운로드는 필요 없다. 누락이 발견되면 공개·개인 monthly DTO와 schema부터 필요한 **집계값**만 보완한다. `fixtures/monthly-rates.example.json`의 테스트값을 운영 화면의 mock 데이터로 넣지 않는다.

## S10. 실제 조회 중임을 알리는 공통·영역별 상태 표시

### 10.1 목표와 범위

지도 범위/기간/지역/필터를 바꾸거나 표·후보 목록·내 신고·맞춤 통계를 조회할 때 사용자가 아무 반응이 없다고 느끼지 않게 한다. **마지막 정상 화면을 유지하는 기능과 로딩 표시는 동시에 필요**하다.

이번 변경은 spinner 컴포넌트 하나를 추가하는 것으로 끝나지 않는다. 실제 request controller의 준비·inflight·검증·반영·종료 상태와 연결하고 현재 보이는 요청을 정확히 표시한다. 브라우저가 서버 DB의 세부 진행률을 알 수 없는데 ‘DB 80% 완료’처럼 표시하지 않는다. 사용 문구는 ‘통계를 불러오는 중’, ‘내 신고를 비교하는 중’ 등 사용자 관점으로 쓴다.

### 10.2 상태별 시각 동작

| 실제 상태 | 사용자 표시 | 이전 결과·조작 |
|---|---|---|
| 로그인/세션 확인 단계 | `로그인 상태를 확인하는 중` | 실제 통계 요청 전에는 DB 조회중으로 오인시키지 않음 |
| 입력 초안만 변경, 적용 전 | `변경한 조건을 적용해 주세요` | 조회 spinner 없음 |
| debounce/자동 갱신 slot 대기 | `선택한 범위로 갱신 준비 중` | 이전 결과 유지, 최신 대기 조건 명시 |
| 최초 데이터 조회 | 뼈대 화면 + `통계를 불러오는 중` | 셸·필터는 보존; 0건 표를 먼저 그리지 않음 |
| 기존 화면 갱신 조회 | 상단 공통 상태 + 영향 패널의 작은 spinner/얇은 진행선 | 마지막 정상 snapshot 유지, 이전 조건임을 명시 |
| 범위/주소 상세만 조회 | 해당 패널 헤더 `상세 정보를 불러오는 중` | 지도는 유지, 다른 범위의 숫자를 새 제목 아래 붙이지 않음 |
| 기관·담당자 검색/페이지 조회 | 해당 목록 `목록을 불러오는 중` | 현재 결과/선택 항목 보존, ‘검색 결과 없음’으로 바꾸지 않음 |
| 비교 대상 후보 검색 | 후보 영역 `검색 중` | 선택한 목록·초안·입력 포커스 보존 |
| 내 신고 비교 조회 | 내 영역 `내 신고를 불러오는 중` | 전체 값은 유효하면 먼저 사용, 내 값으로 복사 금지 |
| 맞춤 통계 실행 | 결과 헤더 `선택한 조건으로 통계를 만드는 중` | 이전 표·차트는 이전 query label과 함께 유지 |
| 표→그래프에서 미보유 시리즈 조회 | 결과 영역 `그래프 데이터를 불러오는 중` | 같은 query/version 유지 |
| 네트워크 종료 후 실제 무거운 변환/시각화 준비 | 필요한 영역만 `그래프를 준비하는 중` | 조회가 완료됐는데 전 화면을 계속 DB 로딩으로 표시하지 않음 |
| 429 또는 제한된 재시도 대기 | `요청이 많아 잠시 기다리는 중 · N초 후 다시 시도` 또는 적절한 재시도 문구 | 요청중과 구별; Retry-After 준수 |
| 성공 후 반영 완료 | 진행 표시 종료, 필요시 짧은 `업데이트됨` | 새 scope/query와 수치를 함께 반영 |
| 오류/시간 초과 | 로딩 종료, 원인에 맞는 오류·재시도 | 이전 결과는 이전 조건임을 알림; 무한 spinner 금지 |
| 다른 요청으로 대체·사용자 취소 | 해당 task 종료; 최신 task가 있으면 계속 진행 표시 | 취소를 조회 실패·0건으로 보여주지 않음 |
| 세션 만료/로그아웃/동의·권한 상실 | 진행·데이터·캐시 정리 후 기존 gate | 보안 오류에서는 이전 private 결과 유지 금지 |

### 10.3 배치·디자인

**상단 공통 상태**: 앱 TopBar/공통 헤더의 늘 같은 슬롯에 작은 spinner+한국어 상태 문구와 indeterminate 진행선을 둔다. 스크롤 위치가 아래여도 조회 사실을 알아볼 수 있어야 한다. ‘필터 적용 중’ 칩만 아주 작게 바꾸는 것으로 끝내지 않는다.

**영역별 상태**: 조회 중인 지도·범위 상세·기관표·월별 차트·맞춤 통계 결과·후보 영역의 헤더에 맞는 문구를 표시한다. 같은 요청으로 여러 카드가 갱신될 때 큰 spinner를 카드마다 겹치지 말고, 공통 상태+작은 `갱신 중` 배지/상단 얇은 진행선을 조합한다.

- 기존 결과를 걷어내고 페이지 전체 skeleton으로 돌아가지 않는다. 지도 DOM/SDK 인스턴스·줌·중심·스크롤·선택 상태를 유지한다.
- 전 화면을 어둡게 잠그는 모달/overlay나 pointer-events:none을 적용하지 않는다. 지도 이동·조건 재선택·뒤로가기·입력은 가능해야 한다.
- 이전 수치를 읽을 수 있는 대비를 유지하고 과도한 blur/opacity 저하로 사실상 가리지 않는다. `새 조건 조회 중 · 현재 숫자는 이전 조건 기준`처럼 scope provenance를 보인다.
- 같은 적용 버튼의 중복 클릭은 필요 시 그 버튼만 막고 `조회 중…`으로 표시한다. 새 조건을 지정해 기존 요청을 대체하는 정상 동작까지 막지 않는다.
- 진행 표시 영역은 높이를 예약하거나 헤더 내부에 배치해 켜질 때마다 문서가 아래로 밀리지 않게 한다. 별도 sticky 줄을 추가하면 S03의 실제 가림높이 계산에도 포함한다.
- 한국어 입력·checkbox·candidate selection에 포커스를 새로 주지 않는다. CSS wait cursor만 바꾸는 것은 충분한 표시가 아니다.
- 테마·모바일에서 배지와 글씨가 보이도록 하고, 화면 폭이 좁으면 문구를 줄이되 상태 자체를 없애지 않는다.

### 10.4 실제 상태를 정본으로 하는 배선

`RefreshController`의 `refreshing`은 현재 코드상 실제 요청중뿐 아니라 예약 대기를 포함한다. `scheduled`, `pausedUntil`, `error`, `generation`, `requested`, `displayed`를 함께 읽어 위 상태를 구분한다. 필요하면 backwards-compatible한 phase/active-request 정보만 확장한다. 기존 debounce·budget·429·409 정책을 무시하는 별도 fetch controller를 만들지 않는다.

대시보드 하나의 boolean을 모든 기능에서 공유하지 않는다. 필요 시 얇은 page-scoped `QueryActivityRegistry` 또는 동등한 observer를 둔다. 이것은 **표시용 상태 집계기**이며 새 요청·polling·retry를 발생시키는 주체가 아니다.

개념 모델(신규 이름 예시, 실제 TS 계약은 기존 controller와 통합):

```ts
type ActivityPhase =
  | 'scheduled' | 'fetching' | 'processing' | 'retry_wait'
  | 'success' | 'error' | 'cancelled';

type ActivityResource =
  | 'dashboard' | 'scope-detail' | 'place-detail' | 'entities'
  | 'personal' | 'statistics' | 'candidates' | 'chart-series'
  | 'map-places' | 'map-boundaries';

// 각 instance는 resource/key/generation으로 구별한다.
// 원본 토큰·원번호·private id를 화면 또는 로그에 노출하지 않는다.
interface QueryActivity {
  id: string;
  resource: ActivityResource;
  requestKey: string;
  generation: number;
  phase: ActivityPhase;
  requestedLabel: string;
  displayedLabel?: string;
  retryAt?: number;
}
```

- 동일 `resource+requestKey`의 중복 구독이 중복 request/spinner count를 만들지 않게 한다. 서로 다른 목록·scope 요청은 독립 instance다.
- `AbortController`로 클라이언트 대기를 취소했다고 이미 시작된 서버 DB 작업까지 취소됐다고 단정하지 않는다. 최신 요청 병합·budget은 유지하고 취소 문구도 클라이언트 작업 기준으로 표현한다.
- A→B→C로 조건이 바뀌면 현재 C의 generation을 추적한다. A의 catch/finally가 B/C의 busy를 false로 만들 수 없다. abort는 그 token만 종료한다.
- pending task들의 집합/정본 상태로 busy를 파생한다. 모든 fetch에서 공유 boolean을 `true; finally false`로 덮는 방식은 금지한다.
- 같은 데이터 query의 메타 읽기→본문 읽기→Zod 검증→scope/version 검사→state commit을 한 사용자 작업으로 취급한다. HTTP header를 받았다는 이유로 미리 완료 처리하지 않는다.
- 새 displayed snapshot commit 시 조건·숫자·표·차트 model의 버전이 함께 맞아야 한다. chart animation 전체가 끝날 때까지 전역 DB spinner를 붙잡을 필요는 없다. 실제 rendering 지연이 있으면 로컬 단계로 분리한다.
- 전체 집계가 끝나고 내 신고만 조회중이면 상단 문구를 `내 신고를 불러오는 중`으로 바꾸고 관련 영역 표시만 남긴다. 다른 독립 목록 조회 때문에 이미 완료된 모든 카드에 갱신 표시가 남아 있으면 안 된다.
- 전체 오류가 아니면 한 패널의 오류가 지도·다른 통계를 지우지 않는다. 상태 우선순위는 권한 오류→현재 관련 오류/재시도 대기→현재 실제 작업으로 정하고 오해 없는 문구를 쓴다.
- 지역 선택, viewport 자동 갱신, 기간 변경, 법규·기관 필터, 이름 검색, 페이지 처리, 내 비교, 맞춤 통계 실행, 후보 검색, 그래프 추가 데이터 조회까지 요청 시작/반영/실패/취소 경로를 감사한다.

### 10.5 아무 작업이나 ‘DB 로딩’으로 표시하지 않기

- 자동 갱신 OFF에서 지도만 움직여 통계를 조회하지 않으면 `통계 조회 중`을 켜지 않는다. 경계 파일이나 주소 정밀화를 실제 가져오면 지도 안에 `지도 정보를 불러오는 중`으로 구별한다.
- 캐시된 결과로 돌아오거나 S09의 지표 checkbox만 바꾸는 것은 DB 조회가 아니다. 표현 변경이 즉시 끝나면 spinner가 필요 없다.
- 통계 설정 초안 편집은 본조회가 아니다. `적용 전 변경사항`과 `조회 중`을 구분한다.
- 애니메이션을 보여주려고 setTimeout으로 가짜 네트워크 시간을 만들지 않는다. 오래된 결과를 새 결과처럼 보여주지도 않는다.
- 빠른 응답의 깜빡임 방지를 위해 indicator 자체를 약 150ms(상한 200ms) 지연 표시할 수 있다. 이 지연은 요청 시작·응답 반영을 지연시키는 sleep이 아니다. 짧은 로컬/cache 동작에서 가짜 로딩을 만들지 않는다. 1초·수초 지연의 실제 요청은 반드시 쉽게 보이는 상태가 남아야 한다.
- 하나의 최신 작업이 완료되기 전 debounce/reschedule/취소 race로 `완료→조회중` 표시가 반복 번쩍이지 않게 한다.
- 측정 없는 0~95% 자동 증가, ETA, ‘DB 검색 완료’ 같은 추정 단계는 금지한다. 전체 단계 진행률을 알 수 없으면 무한형 진행선과 문구를 사용한다.
- 긴 요청은 일정 시간 후 `평소보다 오래 걸리고 있습니다`를 덧붙일 수 있다. 실제 제한·timeout·재시도/취소 액션과 연결하고 완료 예정 시각을 지어내지 않는다.
- 429/재시도 countdown은 실제 retryAt 기준으로 계산하고 폴링 요청을 추가하지 않는다. 기다리는 동안 조건을 바꾸면 가장 최근 조건만 이후 실행한다.

### 10.6 접근성·정리·오류 회귀

관련 결과 컨테이너에 `aria-busy`를 실제 갱신 상태와 연결한다. 보이는 한국어 상태는 `role=status`/`aria-live=polite`/`aria-atomic=true`에 맞춰 필요한 전환만 알린다. 로딩 문구가 busy subtree 안에 있어 읽기 자체가 미뤄지지 않도록 별도 status node 배치를 검토한다. 매 지도 pixel 이동·countdown tick을 반복 낭독하지 않는다.

진행률을 모르면 determinate percent/aria-valuenow를 제공하지 않는다. purely decorative spinner는 aria-hidden으로 두고 텍스트를 읽히게 한다. 중요한 최종 오류는 적합한 alert로 제공하되 취소를 경고하지 않는다. reduced-motion에서는 회전·shimmer를 줄이고 정적인 아이콘·문구로 동일 상태를 전달한다.

페이지 전환·패널 닫기·세션 변경·컴포넌트 unmount 때 해당 task와 timer/listener를 정리한다. 숨겨진 페이지의 오래된 작업 때문에 다른 페이지에서 로딩 표시가 영구히 남으면 안 된다. 권한 경계 변화는 모든 과거 개인 데이터·task를 폐기한다.

ECharts `showLoading/hideLoading`은 필요한 최초 빈 차트/개별 데이터 준비에 사용할 수 있지만, 이미 읽을 수 있는 차트를 큰 mask로 막는 기본 처리는 피한다. 공통 `PanelQueryState` UI가 별도의 chart 재생성·지속 animation 이벤트 loop를 일으키면 안 된다.

### 10.7 통합 시나리오

`강서구 선택 → 전체 화면 갱신 표시 → 전체 결과 반영 → 내 비교 조회 중 표시 → 주소 P1 선택 → 주소 상세 조회 표시 → P2 선택으로 P1 취소 → P2 반영 → 선택 해제 → 범위 상세 복귀 → 통계 페이지 → 기관 후보 검색 → 대상 3개 적용·통계 실행 → 표→그래프`를 느린 네트워크에서 검증한다.

각 순간에 사용자는 무엇을 기다리는지 알 수 있고, 기존 정상 내용·지도 조작·선택은 필요한 범위에서 유지돼야 한다. 최신 작업만 결과를 반영하고 종료/오류/취소 후 진행 표시가 남지 않아야 한다.

## S12. 구현 순서와 인수 기준

1. 현재 동작 재현: 같은 핀 재클릭, selected와 mine 겹침, sticky 제목 가림, 지역 상세 진입, 맞춤 통계 진입, 월별 단일 비율, 느린 조회 시 표시 부재.
2. 기존 requested/displayed/generation과 개별 조회 경로를 조사하고 S10 상태 계약을 먼저 정리한다. 코드 사실과 추정 원인을 구분한다.
3. base scope/selection 분리·해제·강조, 공통 sticky 이동과 전국/시도/시군구/bbox 상세를 구현한다.
4. field/metric registry·query/response 계약·후보 API·집계 정확성 테스트를 만든다.
5. 통계 화면·비교 대상 선택·표·차트 전환·자동추천·조건 인계를 구현한다.
6. 월별 복수 비율 선택을 동일 지표 registry/selector·전체/내 신고·표·레시피와 연결한다.
7. 각 화면의 상태를 S10 공통/패널 표시로 연결하고 실제 slow/race/retry/cancel 시나리오를 검증한다.
8. 세션/동의/장기간/대상 다수/0건/1건/동명이인/권한/레이스·메모리 회귀를 검증한다.
9. 실제 브라우저 PC·모바일·다크/라이트·확대율에서 UI/Network/console/성능을 검수한다. 정상 정적 캡처뿐 아니라 조회 중 캡처나 짧은 녹화와 종료 증거를 남긴다.

함께 제공한 `ACCEPTANCE_TESTS.md`의 모든 S01~S10 및 IN 통합 테스트를 수행한다. `fixtures/monthly-rates.example.json`은 계산 oracle용 합성 자료다. 구현 환경에 맞춰 fixture를 어댑트하되 expected 값을 현재 코드 출력으로 덮어써 통과시키지 않는다. 보조 테스트 문서를 읽을 수 없어도 이 본문 각 절의 요구를 누락하지 말고 동등한 테스트 계획을 만들어 실행한다.

신규 예시 경로는 실제 코드에 맞춰 조정하되 UI→client→schema→server→공개·개인 집계의 필수 연결을 생략하지 않는다. S09·S10은 이번 작업의 필수 인수 조건이며 추후 작업으로 미루지 않는다. 화면 상태 표시를 추가하려고 재조회 횟수·DB 부하가 늘어나면 실패다.

운영 적용 순서는 호환성을 고려해 migration/RPC → Edge → 프론트로 계획한다. 기존 endpoint를 한 번에 깨뜨리지 말고 additive 계약·schema version·capabilities를 활용한다. 필요한 운영 단계와 실제 수행 여부를 구분한다.

완료 보고에는 S01~S12별 변경 파일, 동작 경로, 테스트 결과, 브라우저 증거, 운영 적용사항을 표로 적는다. 실제 운영 권한이 없어 못한 부분은 ‘운영 미검증’으로 명시한다. 문서 생성/mock 성공만으로 전체 완료라고 보고하지 않는다. 추가 업로드·정책 변경이 필요하다고 단정하기 전에 기존 저장/공개 projection을 대조한다.
