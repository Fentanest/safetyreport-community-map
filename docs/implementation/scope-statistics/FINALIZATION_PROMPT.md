## 0. 이번 마감의 범위

C01~C08 전체를 처음부터 다시 만들지 않는다. 기존 계정 경계 수정, 비교 히트맵, assertion 검사, 0건/확인 불가 구분, scrollspy·뒤로가기 복원은 보존한다.

이번 범위는 다음이다.

- F01: 차트 유형 전환 시 차트 컨테이너 생명주기 경로 재현·수정.
- F02: 안전한 분석 구성 공유 링크 구현.
- F03: 맞춤 통계 차트 범례의 시리즈 숨기기·복원 구현.
- F04: 실제 Edge Runtime·DB·카카오 SDK 검증에서 남은 환경 차단을 별도 처리.
- F05: 배포 호환성 확인과 최종 코드/증거 정리.
- F06: Excelize의 브라우저용 WASM을 이용한 **통계표 + 편집 가능한 엑셀 차트 + 조회 조건**의 `.xlsx` 다운로드 구현.

**이번 내보내기 기능은 선택 사항이 아니라 F06의 필수 범위다. CSV 대신 Excelize 기반 XLSX를 구현한다.** CSV 파일의 확장자만 바꾸거나 차트를 스크린샷으로만 삽입한 파일을 완료로 취급하지 않는다. 별도 CSV 메뉴는 추가하지 않아도 된다.

새로운 통계 지표, 새 디자인 전면 개편, 업로드/동의 범위 변경을 추가하지 않는다. 웹 서비스는 GitHub Pages 정적 배포를 유지한다. Excelize/Go 서버를 새로 상주시켜 파일을 만드는 것이 아니라, **사용자 브라우저에서 Excelize WASM으로 파일을 생성**한다.

향후 AdSense를 고려한 제약도 F06의 인수 조건이다. 엑셀 기능 때문에 메인 사이트에 COOP/COEP·교차 출처 격리를 추가하거나 `SharedArrayBuffer`를 요구하지 않는다. 광고를 실제 삽입하거나 AdSense 계정·정책을 변경하는 작업은 포함하지 않는다.

작업 순서는 F06의 작은 비격리 브라우저 시제품 검증 → F01 및 공통 차트 모델 정리 → F02/F03/F06 구현 → F04 실제 환경 검증 → F05 배포 준비를 권장한다. 라이브러리 지원을 확인하는 시제품만으로 제품 구현을 끝냈다고 보고하지 않는다.

작업 계획만 제출하고 멈추지 말고 로컬에서 가능한 구현·검증은 완료한다. 운영 DB 변경, main 병합, 운영 배포는 이 지시서만으로 실행하지 않는다. 새 PR이 필요하면 제목·본문·검증 범위를 준비하고, PR 생성도 현재 사용자의 명시적 허용 범위를 확인한다. 기존 #17에 후속 변경이 자동으로 병합되는 것으로 취급하지 않는다.

## F01. 히트맵 → 막대 전환에서 빈 차트가 생기는지 재현하고 수정

### 확인한 코드 경로

`src/components/stats/PivotChart.tsx`의 상위 컴포넌트는 공통 `useEChart()`를 호출한다. 그러나 히트맵이면 `HeatmapPair`를 반환하고 이 공통 훅의 `hostRef`가 붙은 DOM은 렌더링하지 않는다. 요약값 분기도 마찬가지다.

`src/lib/charts.ts`의 생성 effect는 의존성이 `[]`이고, 첫 실행에 `hostRef.current`가 없으면 반환한다. `StatisticsPage.tsx`에서 유형만 바꿀 때는 같은 `PivotChart` 인스턴스에 설정을 전달한다.

따라서 처음 히트맵으로 열린 상태에서 막대/선으로 바로 전환하면, 뒤늦게 생긴 일반 차트 DOM에 초기화 effect가 다시 실행되지 않는 경로가 있다. 반대로 일반 차트에서 히트맵으로 갔다 돌아오면 기존 인스턴스가 제거된 DOM을 참조할 가능성이 있다. 이것은 정적 코드 검토로 찾은 경로다. 이번 실행에서 실제 재현 여부를 기록하라.

### 재현

1. 유효한 `기관 × 위반법규 / 과태료처분율` 결과를 만든다.
2. 표에서 그래프로 처음 전환해 자동 히트맵을 표시한다.
3. 표로 돌아가지 않고 유형 선택기에서 호환되는 `막대`로 바꾼다.
4. 일반 차트 DOM에 ECharts 인스턴스와 실제 series가 생성되는지 확인한다.
5. 막대 → 히트맵 → 막대, 비교 히트맵 → 일반 차트, 일반 차트 → 요약값 → 일반 차트를 검사한다.
6. 설정을 저장했다가 처음부터 히트맵으로 복원하는 경우에도 확인한다.

빈 카드가 DOM에 존재하는지만 보지 않는다. dev/test 전용으로 연결된 chart 인스턴스, series 데이터, 실제 그려진 화면을 확인한다. 테스트용 hook은 production bundle에 넣지 않는다.

### 권장 수정

렌더러별 컴포넌트를 분리해 차트 인스턴스의 생명주기를 실제 host DOM과 일치시키는 방식을 우선 검토한다.

- 상위 `PivotChart`: 표현 계획·공통 설정과 결과 선택.
- `CartesianChart` 등 일반 차트: 자기 host와 `useEChart` 소유.
- `HeatmapPair`/`HeatmapSide`: 각각 자기 host와 chart 소유.
- 요약값: chart 훅 없이 요약 렌더러 사용.

또는 host의 실제 mount/unmount를 추적하는 안전한 callback ref 기반 훅으로 해결해도 된다. ref.current를 dependency 배열에 무작정 추가하거나 모든 React render마다 chart를 init하는 식으로 때우지 않는다.

표현 종류가 완전히 달라질 때 필요한 차트 인스턴스 교체는 허용한다. 같은 host의 지표 체크·필터 결과 반영·테마 변경은 기존 방식대로 업데이트한다. 문제를 숨기려고 전체 페이지나 지도를 remount하지 않는다. 분석 query, 적용 결과, 비교 대상, 정렬은 유형 변경으로 초기화하지 않는다.

전환 20회 후 오래된 DOM의 chart/ResizeObserver/리스너가 남지 않는지도 확인한다.

## F02. 분석 구성 공유 링크

### 공유하는 것

공유는 ‘분석 결과 원문’이 아니라 ‘다른 사람이 자신의 권한으로 같은 조건의 분석을 재실행하는 구성’이다.

공유 가능한 항목은 버전 있는 allowlist로 정의한다.

- 행·열·지표의 registry id와 순서.
- 기간과 날짜 기준.
- 공개 허용된 지역·분류·법규·기관·담당자 비교 대상 조건.
- 차트 유형, 주 지표, 단위가 같은 지표 겹쳐 보기 설정.
- 표/그래프 표시 모드 및 필요한 정렬.
- 표현용 범례 숨김 상태를 넣는다면 안정된 시리즈 식별자만 사용.

기본은 현재 ‘실제로 적용되어 표시 중인 분석’을 공유한다. 작성 중 미적용 draft를 몰래 공유하지 않는다. 작성 중 구성을 공유하려면 별도의 명시적 선택으로 구분한다.

### 공유하지 않는 것

JWT, access/refresh token, service_role key, 실제 user id/계정 해시, connection/session id, 원본 차량번호, 신고번호, source_report_id, 원신고 배열, 비공개 필드, 작성자의 내 신고 결과를 URL이나 공유 저장소에 넣지 않는다.

주소·place_key·세밀한 bbox 등 개인적인 위치 선택은 이번 기본 공유 구성에서 제외한다. 이런 조건이 포함된 분석이라면 무엇이 공유되지 않는지 알리고, 사용자가 공유 범위를 조정/확인하기 전에는 원래 분석과 동일하다고 표시하지 않는다. 조건을 지우고 전국으로 넓힌 링크를 조용히 생성하지 않는다.

`population=mine` 또는 `compare`를 공유할 때는 ‘내 신고는 링크를 연 사람 기준’이라는 설명과 확인을 제공한다. 수신자는 작성자의 내 신고를 볼 수 없다. 작성자 기준의 값이나 식별자는 절대 이관하지 않는다.

### 링크·수신 처리

- GitHub Pages의 직접 열기·새로고침, 기존 `screen=statistics`, OAuth callback/fragment와 충돌하지 않는 방식을 사용한다.
- 버전 있는 작은 recipe를 URL로 인코딩하는 방식이면 충분하다. 단축링크 서비스나 새 공유 DB는 이번 필수 범위가 아니다.
- 클라이언트와 서버 모두 allowlist, 크기·깊이·배열 개수·선택 대상 개수·필드 타입을 검증한다.
- 압축을 쓴다면 압축 해제 후의 크기 제한도 둔다. 임의 SQL/HTML/JavaScript를 실행하지 않는다.
- 이름·라벨·값·집계 결과는 링크의 문자열을 신뢰하지 말고 허용된 대상 key를 서버에서 다시 확인한다.
- 잘못된 구성/지원하지 않는 버전/권한 밖 대상/한도 초과는 명확히 알리고, 조용히 기본 구성이나 전체로 대체하지 않는다.
- 링크를 열어도 기존 로그인·열람 자격·동의 검사를 우회하지 않는다. 카카오 로그인 왕복 후에도 허용된 recipe를 유지한다.
- URL에 길이 한도가 걸리면 자르지 말고 비교 대상을 줄이도록 알린다. 구성 복원이 불완전한 상태를 성공으로 보고하지 않는다.
- 결과 snapshot을 공유하지 않으므로 나중에 열면 갱신된 자료로 수치가 달라질 수 있다는 설명을 짧게 둔다.
- 클립보드 실패 시 사용자가 확인한 안전한 링크를 복사할 수 있는 대체 경로를 둔다.

### 테스트

행/열/지표/필터/표현 순서 왕복, 한글/특수문자, 직접 새로고침, OAuth 왕복, 다른 계정에서 재조회, 미로그인 접근, 임의 필드·너무 긴 recipe, 확인 불가 대상, 비공개 값 없는 URL, 미적용 draft와 적용 결과 구분을 검사한다.

## F03. 범례 숨기기·복원

사용자가 실제로 여러 시리즈를 보는 맞춤 통계 차트에서 범례 클릭/키보드로 시리즈를 숨기고 다시 표시하게 한다. `legend.selectedMode=false`만 유지한 채 CH-10을 완료 처리하지 않는다.

- 범례 숨김은 프론트 표현만 바꾼다. API 요청·서버 재집계·분석 대상·표·합계·분모·공유 데이터 모집단을 바꾸지 않는다.
- 안정된 시리즈 key와 표시 이름을 분리한다. 소속이 다른 동명이인 또는 같은 라벨 때문에 여러 시리즈가 함께 잘못 숨겨지지 않게 한다. ECharts legend가 시리즈 이름으로 동작하는 부분과 내부 key 매핑을 명확히 한다.
- 범례 상태를 React 또는 동등한 정본 표현 상태로 보관한다. 현재 `setOption({notMerge:true})` 경로를 고려해 테마 변경/표↔그래프 전환/정렬만으로 숨김 상태가 사라지지 않게 한다.
- query가 변해 없는 시리즈가 되었으면 숨김 key를 정리하되, 다른 시리즈를 같은 위치라는 이유로 대신 숨기지 않는다.
- `전체 보기` 또는 `숨김 해제`를 제공한다. 전부 숨기면 ‘표시할 항목을 선택해 주세요’와 복원 조작을 표시한다. 0건·자료 없음·조회 실패로 표시하지 않는다.
- 누적 및 100% 누적에서도 원래 분모는 유지한다. 한 항목을 숨겼다는 이유로 남은 항목을 새로 100% 정규화하지 않는다.
- 비교 전체/내 신고의 동일 지표도 안정적으로 구분한다.
- 히트맵의 연속형 색 범례는 시리즈 on/off 범례와 다르다. 의미 없는 셀별 토글을 억지로 만들지 않는다. 지원 범위를 문서화한다.
- 월별 추이의 지표 체크박스는 이미 있는 표시 선택기다. 같은 의미의 또 다른 토글을 중복시켜 서로 상태가 어긋나지 않게 한다. 범례 토글을 연결한다면 체크 상태와 단일 정본을 쓰고 미선택 지표를 몰래 생성하지 않는다.

테스트: 시리즈 B 숨김 후 요청 0, 표/총계/분모 불변, 다시 표시, 전부 숨김 복구, 테마·정렬·표/그래프 왕복, 100% 누적 분모 보존, 동명이인·다중 모집단 구별, 리스너 중복 없음.

## F04. 실제 환경 검증과 차단 처리

`browser-mock`, `sql-local`, `edge-runtime-local/CI`, `real-sdk`, `production`을 분리해서 기록한다.

### Edge Runtime

`src/domain/statistics.ts`의 `./public.ts` 변경은 보존한다. 프런트 Vite build 성공, manifest/compose 구성 검사, 로컬 SQL 검사만으로 Edge 번들·실행 성공을 대신하지 않는다.

프로젝트의 고정 CLI/런타임·lockfile·import map을 사용해 두 함수 `public-analytics`, `my-analytics`의 실제 의존성 해석/번들 또는 로컬 기동 검사를 추가한다. 함수가 실제로 뜬 뒤 catalog/candidates/query와 인증 거부·전체/내 신고 요청을 호출한다. 운영으로 배포해 보면서 테스트하는 방식은 기본값으로 삼지 않는다.

앞서 차단된 Docker 통합 검사는 인증서/네트워크가 정상인 CI 또는 로컬에서 재실행한다. 프록시 인증서를 무조건 신뢰시키거나 TLS 검증을 전역 해제하는 우회를 기본 해법으로 쓰지 않는다. 런타임에 맞는 신뢰 체인 설정 또는 프록시 없는 허용된 환경으로 옮긴다.

불가능하면 필요한 외부 조치를 한 번에 정리하고 BLOCKED로 남긴다. 동일한 실패 다운로드를 무한 반복하지 않는다. 새 환경에서도 테스트 fixture와 격리된 DB만 사용하고 운영 신고 자료를 지우거나 변조하지 않는다.

### 실제 지도·인증

카카오 JS 키와 등록된 도메인, 필요한 네트워크가 갖춰진 환경에서 `verify_real_sdk.mjs`를 실행한다. 실제 mouse/touch·휠·drag·빠른 재클릭·빈 지도 클릭·클러스터 확대·Polygon 선택을 검사한다. MOCK `__click` 통과로 실제 SDK 통과를 대신하지 않는다.

별도 테스트 계정 두 개로 닉네임이 같은 A/B 전환, 늦은 A 응답 차단, 로그아웃·로그인 후 설정, 테스트용 동의 철회·권한 상실을 확인한다. 실제 인증 user id의 클라이언트 해시는 상태 구분용이지 서버의 인가 근거가 아니다. 서버는 계속 검증된 JWT로 사용자를 확정한다.

브라우저 실제 확대율 125/150/200%는 지원되는 브라우저에서 수동 또는 적합한 자동화로 확인한다. viewport/DSF 에뮬레이션은 별도 결과로 남긴다. 지도 중심·zoom 보존은 인스턴스 개수뿐 아니라 가능한 경우 실제 중심값·zoom값도 비교한다.

### assertion 마감

기존 잘못된 기대값을 넣는 자가 검증은 유지한다. 각 실행에 코드 SHA·dirty 여부·SDK/자료/서버 환경을 기록한다. 주요 ID마다 기능 기대값 검증이 최소 하나 있는지 확인한다. 콘솔 오류 없음만으로 기능 ID가 PASS가 되거나, 필수 ID가 NOT_RUN인데 전체 완료로 표현되지 않게 한다. 일부 실행을 전체 실행처럼 합치지 않는다.

## F05. 배포 순서·호환성·보고

### ‘구 서버’의 버전부터 특정

‘Pages를 먼저 올려도 된다’는 말은 실제 운영 Edge가 통계 catalog/candidates/query를 이미 지원할 때만 검토할 수 있다. C05의 선택적 상태 필드 하위 호환과, 통계 API 자체가 없는 구버전과의 호환은 다른 문제다.

운영 배포 이력 또는 권한 있는 읽기 검증으로 다음을 확인한다.

- 실제 DB의 이전 migration 적용 이력 및 필요한 RPC 시그니처.
- 실제 `public-analytics`, `my-analytics`의 배포 버전.
- 새 프런트가 호출할 catalog/candidates/query·개인 비교 경로의 존재와 응답 계약.
- 이전 라운드 `202609300100`은 보고서상 사용자 적용 보고가 있으므로 임의 재실행하지 않는다. 실제 확인 여부를 구분한다.

보고서의 ‘이번 라운드 DB 변경 없음’을 ‘모든 과거 migration이 운영에 적용됨’으로 확대 해석하지 않는다.

### 권장 순서

1. 필요한 DB/RPC의 적용 여부 확인. 미적용이 확인되면 승인 후 필요한 증분 변경만 적용.
2. 고정된 최종 코드로 Edge 두 함수를 배포하고 실제 응답 계약 확인.
3. 동일 기능 집합의 Pages 배포.
4. 실제 SDK·두 계정·지역 상세·맞춤 통계·다중 월별 지표와 실제 XLSX 다운로드의 smoke 확인. WASM 자산의 base path·MIME/압축·동일 버전 배포도 확인한다.

이 문서 자체는 main 병합·운영 배포·운영 DB 변경 승인이 아니다. 기존 main push가 Pages 배포를 자동 실행한다면 병합이 배포 동작임을 사전에 알리고 승인 시점과 순서를 맞춘다. 후속 기능을 기다리지 않고 C01 보안 수정만 별도로 먼저 배포해야 한다면, 그때의 실제 구서버와 프런트 호환성을 확인한 좁은 별도 수정으로 계획한다.

코드가 바뀌면 `4eef797`의 기존 증거를 새 코드 검증 결과로 재사용하지 않는다. 최종 코드 SHA와 그 SHA를 검증한 새 증거 SHA를 구분해 제출한다. 기존 #17은 이미 병합된 PR이므로 새 변경분과 base를 확인한 새 PR을 사용한다.

## F06. Excelize 기반 엑셀 다운로드 — 표·셀 연결 차트·조회 조건

### E01. 필수 제품 동작과 진입점

사용자가 보고 있는 정상 집계 결과를 **`.xlsx` 파일**로 내려받게 한다. 버튼은 `엑셀 다운로드`이며, 설명은 `통계표 · 편집 가능한 차트 · 조회 조건`이다.

필수 진입점:
1. **맞춤 통계 결과 도구줄**: 표 보기/그래프 보기 어느 상태에서도 다운로드 가능.
2. **월별 추이 카드**: 현재 건수/처리결과 비율 모드, 체크한 지표, 전체/내 신고 비교를 반영.
3. **선택 범위·주소의 담당자 차트**: 현재 실제 표시된 범위 및 수용률/과태료처분율 모드를 공통 exporter에 전달. 이 패널의 미리보기만 받은 경우 전체 목록 확보 또는 명시된 일부 범위를 처리한다.

각 진입점마다 Excel 생성 코드를 복사하지 않는다. 공통 `ExportSnapshot → WorkbookPlan → ExcelizeWriter`를 만들고 화면별 adapter만 둔다. 기타 대시보드 카드마다 새 버튼을 붙이거나 지도 자체를 Excel 지도로 변환하는 것은 필수가 아니다.

- 기본 파일은 **통계표 + 차트/히트맵 + 조회 조건 + 차트 데이터** 4개 시트다. 기존에 쓰는 동일 의미 시트명이 있으면 한글 이름을 일관되게 조정해도 된다.
- 차트는 셀 범위를 참조하는 실제 OOXML 차트다. 차트 제목·계열·원본 셀을 Excel에서 편집할 수 있어야 한다.
- 히트맵은 셀 기반 교차표와 조건부 색상 서식으로 구현한다. Excel에 없는 전용 히트맵 차트 객체를 지어내거나 그림으로만 대체하지 않는다.
- 이 파일은 **조회 당시의 집계 snapshot**이다. Excel에서 Supabase를 재조회하거나 웹 앱의 모든 피벗 기능이 재현되는 파일은 아니다. 매크로·외부 데이터 연결·Power Query·Office Script를 요구하지 않는다.
- 사용자에게 전송 가능한 집계 결과만 사용한다. 원 신고, 비공개 차량번호, 신고번호, 계정 토큰을 추가 수집하지 않는다.
- 한 건도 정상 지원한다. 아무 자료가 없거나 차원 없는 단일 지표면 빈 차트를 꾸미지 말고 같은 파일 안에 0건/자료 없음/요약값을 정확히 적는다.

### E02. Excelize 버전·실제 API 확인과 작은 시제품

선택한 **`excelize-wasm` 배포 패키지와 그 안의 Excelize 빌드**를 고정한다. 현재 Go Excelize 문서의 최신 API가 WASM wrapper에 전부 노출됐다고 가정하지 않는다.

실제 설치본의 `package.json`, `.d.ts`, loader, WASM 배포물과 라이선스를 확인하고 다음을 먼저 작은 합성 예제로 검사한다.

- 일반 비격리 브라우저에서 로더 초기화.
- 셀 쓰기/스타일/분자·분모로 만든 비율 수식.
- 셀 참조를 가진 꺾은선 및 막대 차트.
- 전체/내 신고 비교 히트맵의 조건부 서식.
- 필요한 보조축 복합 차트 지원 여부.
- 메모리 버퍼에서 실제 `.xlsx` 다운로드 및 Excel에서 열기.

공식 wrapper 예제의 `init(...)`, `NewFile()`, `SetSheetRow(...)`, `AddChart(...)`, `WriteToBuffer()`가 출발점이다. **옵션 명·대소문자·반환 구조·combo 인자·차트 enum은 고정한 설치본을 정본으로 확인한다.** Go 예제 코드를 그대로 JS에 붙이지 않는다. 예시의 `ret.error` 같은 오류 반환은 예외가 자동 throw된다고 가정하지 말고 실제 반환 형태에 맞춰 검사한다. 각 쓰기·스타일·차트·버퍼 생성 단계 실패를 공통 wrapper에서 전파한다.

JS wrapper에 기능이 빠졌다면 같은 Excelize의 최소 브리지를 추가 빌드하는 방법을 검토하고 소스·빌드 재현성을 남긴다. 임의 OOXML 조각 덧붙이기나 다른 라이브러리로 몰래 교체하는 방식은 쓰지 않는다. 기본 차트들 미지원 상태를 표만 만드는 성공으로 처리하지 않는다.

버전은 manifest/lockfile에 고정하고 라이브러리 라이선스 고지를 배포에 포함한다. WASM 바이너리를 임의 사이트에서 복사하거나 floating `latest` CDN을 런타임에서 사용하지 않는다.

### E03. 향후 AdSense를 고려한 비격리 실행과 자산 배포

이 절은 ‘AdSense 승인/수익/동작 보장’이 아니라 **엑셀 기능이 사이트의 외부 연동 조건을 불필요하게 바꾸지 않게 하는 기술 제약**이다.

1. 실행 환경의 `window.crossOriginIsolated === false`에서 파일 생성과 차트 다운로드가 성공해야 한다. Worker를 사용하면 그 환경도 비격리 실행을 확인한다.
2. `SharedArrayBuffer`·공유 WebAssembly.Memory·공유 메모리 기반 멀티스레드를 필수 의존성으로 삼지 않는다. 일반 Web Worker와 공유 메모리 멀티스레드는 다른 개념이다.
3. 엑셀 기능 때문에 COOP/COEP 헤더나 `coi-serviceworker`류의 격리 service worker를 추가하지 않는다. 별도 도메인·iframe 격리·로그인 팝업 정책 변경으로 우회하지 않는다.
4. WASM/loader/관련 export chunk는 **사용자가 엑셀 다운로드를 실행할 때** 지연 로딩한다. 지도 최초 진입이나 단순 통계 표/그래프 전환만으로 다운로드하지 않는다. 두 번째 실행은 동일 정적 자산 캐시를 활용한다.
5. WASM과 로더는 빌드 시 고정 패키지에서 가져와 **같은 Pages origin**의 버전 관리된 자산으로 배포한다. 앱이 하위 base path에 배포돼도 경로가 맞아야 한다. `/node_modules/...`나 루트 `/...` 경로를 그대로 박지 않는다.
6. 패키지가 `.wasm.gz`를 제공하면 로더의 압축 해제 방식과 HTTP Content-Encoding 동작을 실제로 확인한다. 이중 압축 해제·HTML 404 응답·잘못된 MIME을 성공으로 처리하지 않는다. Go runtime glue와 WASM 바이너리의 버전을 맞춘다.
7. 기존 CSP가 있으면 현재 필요 범위만 검토한다. WASM 실행 허용이 필요할 때는 `'wasm-unsafe-eval'` 같은 좁은 옵션을 확인하고, 광범위한 `'unsafe-eval'`, `'unsafe-inline'`, `*` 허용을 새로 추가하는 식으로 완화하지 않는다. Worker/asset 경로도 실제 배포 방식에 맞게 최소 허용한다. 기존 보안정책을 몰래 삭제하지 않는다.
8. 카카오 지도·로그인·일반 외부 script/iframe과 함께 작동하는지 확인한다. 실제 AdSense 코드를 새로 넣거나 광고 클릭·반복 노출을 만드는 테스트는 하지 않는다. 무해한 테스트용 외부 리소스 검사는 실제 광고 호환 검증과 구별한다.
9. 개발자 플래그로 브라우저 보안을 끄거나 Chromium에 COOP/COEP 우회 플래그를 넣은 성공은 비격리 검증으로 인정하지 않는다.

가능하면 Excel 생성은 **공유 메모리 없는 전용 Web Worker**에서 수행한다. worker용 loader 지원 여부를 실제 wrapper로 확인하고, 필요하면 module/classic worker에 맞는 얇은 adapter를 만든다. DOM에 의존하는 브라우저 코드를 `window=self` 한 줄로 무조건 Worker 호환이라고 주장하지 않는다. UI에는 메시지로 진행 단계만 보내고, 최종 파일 bytes는 transfer 가능한 **별도 소유의 ArrayBuffer**로 전달한다. WASM heap buffer를 직접 detach해서 런타임을 망가뜨리지 않는다.

Worker 지원 제약이 있으면 허용된 동일 Excelize 비격리 경로로 보완한다. 메인 스레드 fallback을 사용하는 경우 실제 목표 크기에서 지도·입력 응답성이 유지되는지 증거를 남기고 제한을 명시한다. 사이트 전체 격리나 서버 생성 방식으로 변경해야 하는 상황이면 독단 변경하지 말고 별도 결정 항목으로 기록한다.

### E04. 내보낼 결과를 고정하고 화면·권한 상태를 보존

기본 입력은 클릭 시점의 **마지막 정상 적용 결과 + 그 결과의 query/scope/version + 표현 설정**이다. 편집 중 draft나 DOM에서 읽은 반올림 문자열은 입력이 아니다.

- 결과가 없으면 다운로드 버튼에 이유를 표시하고 비활성화한다.
- 새 요청 대기/실행 중이면 ‘새 조건 결과를 기다리는 중’으로 기본 다운로드를 잠근다. 명시적 `이전 결과 다운로드`를 제공하는 경우 이전 조건과 시각을 확인시킨다. 새 조건명+옛 수치를 섞지 않는다.
- 내 신고 비교를 켠 상태에서 개인 응답이 미완료이면 기다리도록 한다. 전체만 내보내는 별도 명시 옵션이 없다면 전체만 몰래 저장하지 않는다.
- 클릭 시 불변 snapshot을 잡은 뒤 사용자가 같은 계정으로 조건을 바꿔도 진행 중 파일의 데이터는 바꾸지 않는다. 파일 설명에 캡처한 조건을 사용한다.
- 로그아웃, 계정 교체, 확인된 열람 자격/동의 상실 시 진행 중 export를 취소하고 late Worker 메시지·Blob 다운로드를 막는다. 이전 계정 파일을 새 계정에서 저장하지 않는다.
- 다운로드 전에 이미 알려진 권한/세션 상태를 재확인하되 별도 polling이나 원자료 전체 재조회는 만들지 않는다. 새로운 데이터 fetch가 필요하면 기존 API 인증·동의 검증을 그대로 통과한다. 이미 내려받은 파일을 나중에 원격 회수할 수 있다고 안내하지 않는다.
- 해당 조건의 **완전한 집계 결과 전체**가 기본이다. 현재 페이지 20행, 화면에 보이는 DOM, 서버 top100 요약만 전체라고 내보내지 않는다.
- 결과가 partial이면 동일 query/version의 완전 집계를 기존 허용 API로 확보하거나, 지원되지 않음을 알린다. 추가 fetch 도중 버전이 바뀌면 혼합 파일을 만들지 않는다.
- 현재 모델이 `complete=true` 또는 한도 초과 422 방식이면 그 계약을 보존한다. 다운로드를 위해 서버 budget·최신 답변 canonical 규칙·정책을 우회하지 않는다.
- 기관/담당자 복합 key·월 key·metricId·population으로 매핑한다. 이름 또는 배열 index만으로 전체/내 신고를 합치지 않는다. 내부 key는 파일의 식별 열로 무조건 노출하지 않는다.

**F03 범례 숨김과 연동:** 표/합계/차트 데이터는 분석 대상으로 선택한 전체 집합을 유지한다. 차트는 기본적으로 클릭 시 화면에서 표시 중인 시리즈를 따른다. `조회 조건`에 차트에서 숨긴 계열과 표 데이터에는 포함되어 있다는 점을 적는다. 다운로드 옵션에서 `숨긴 계열도 차트에 포함`을 제공할 수 있다. 모든 계열을 숨겼다면 표는 유지하고 차트 자리에는 ‘현재 모든 계열을 숨김’과 복원 안내를 넣는다. 이를 0건으로 표시하지 않는다.

### E05. 통합 문서의 시트 구성·서식

| 시트 | 필수 내용 |
|---|---|
| `통계표` | 현재 행·열·선택 지표의 전체 결과, 다단계 머리글, 전체/내 신고 구분, 의미가 맞는 소계·합계, 수치·단위 |
| `차트` | 셀 참조 기반 native 차트 또는 셀 기반 조건부 서식 히트맵. 다중 차트의 제목·범위·집단·분모 안내 |
| `조회 조건` | 기간·날짜 기준·지역/주소 조건·법규·분류·기관/담당자 선택·행/열/지표·범례 상태·조회/내보내기 시각·데이터 버전·계산식·결측/제외 기준·snapshot 안내 |
| `차트 데이터` | 차트가 참조하는 읽기 쉬운 집계 셀 블록. 시리즈명·날짜/범주·정확한 수치·필요 분자/분모/결측 사유. **개별 원 신고가 아님** |

조회 조건에는 고정된 날짜 범위와 `Asia/Seoul` 시각을 명시한다. ‘최근 1년’이라는 상대 표현만 저장하지 않는다. `내 신고`는 내보낸 사람 자신의 집계라는 뜻이며 다른 사람이 파일을 열었다고 그 사람의 값으로 바뀌지 않는다. 개인 계정 ID·닉네임·토큰을 써 넣을 필요는 없다.

- workbook 파일명 예: `커뮤니티신고지도_맞춤통계_20260929_153000.xlsx`. 파일명에는 개인 이름·원 신고번호·세밀한 주소를 넣지 않는다.
- 흰색/밝은 문서 바탕, 한글이 읽히는 폰트명과 10~11pt 본문, 제목·헤더 강조, 적절한 열 너비·줄바꿈·고정 행/열·숫자 오른쪽 정렬을 사용한다. 웹 다크모드를 검은 시트 전체로 그대로 복사하지 않는다. 폰트 파일을 포함할 필요는 없다.
- 데이터 표 안에 불필요한 merge를 넣어 정렬·필터를 망가뜨리지 않는다. 계층 헤더는 별도 머리글 행에 표현하고 실제 표 영역의 열 이름은 고유하게 만든다.
- 동명이인은 소속기관과 함께 표시한다. 시트 이름/테이블 이름/차트 이름은 유효하고 고유하게 생성한다. 지역명을 시트명으로 무제한 사용하지 않는다.
- 차트가 데이터 표를 덮지 않게 별도 시트와 충분한 anchor 간격을 쓴다. 여러 그래프는 비율·단위가 읽히는 크기로 배치하고 인쇄 영역도 확인한다.
- `차트 데이터`는 기본적으로 보이게 하고 편집할 셀을 설명한다. 숨김 시트를 보안 장치로 사용하지 않는다. 표와 차트의 숫자가 독립 복사본이 되어 서로 어긋나지 않도록 공통 원본 셀 또는 내부 참조로 연결한다.
- 일반 집계 수치 snapshot을 저장하는 것이지 Excel native PivotTable cache에 모든 원신고를 넣는 작업이 아니다. 후자의 구현을 필수로 늘리지 않는다.

### E06. 수치·분모·수식·빈 값

차트의 수치와 표시용 문자열을 분리한다. 서버에서 받은 정확한 수치와 분자/분모를 바탕으로 Excel 수치 셀을 만든다.

- 건수는 정수, 금액은 숫자+원 단위 서식, 기간은 숫자+일, 별점은 숫자+점, 비율은 **0~1 실수+`0.0%` 서식**으로 저장한다. API가 66.6667을 주더라도 Excel 셀에는 0.666667이어야 한다. 6,666.7%가 되면 실패다.
- %p 차이는 % 비율 서식과 다르다. 차이가 들어가는 경우 실제 단위에 맞춘 별도 숫자 서식을 사용한다.
- 실제 0은 숫자 0으로 보존한다. null/분모0/미지원/해당 조합 없음은 0으로 바꾸지 않는다. 표에는 빈 셀/‘—’와 사유를, 차트 source에는 실제 누락 상태를 사용한다.
- 꺾은선은 빈 달에서 끊고 실제 0%는 0에 찍는다. 날짜축과 누락값 때문에 0이 보간되지 않게 한다. Excel의 `ShowBlanksAs` 또는 해당 버전의 동등 옵션과 chart cache를 검증한다. `=""` 수식이 어떤 Excel 버전에서 0으로 그려질 수 있으므로 무조건 같은 것으로 취급하지 않는다.
- 비율의 수식은 분모가 유효한 집계 셀에서 명시적 분자/분모 참조로 구성한다. 정상 값에서만 수식을 만들고, 분모 0은 blank/reason으로 구분한다. 실패를 숨기는 전역 IFERROR로 데이터 오류를 0에 묻지 않는다.
- 예: C=20, A=12, P=3, R=3이면 K=18. 수용률=12/18, 일부=3/18, 불수용=3/18. F=8이면 과태료처분율=8/20, W=5이면 계도처분율=5/20. 분자/분모 선택을 바꾸지 않는다.
- 1/1과 9/99의 상위 합계는 10/100=10%다. 비율의 평균으로 만들지 않는다. 중앙값/P90/distinct 소계는 원자료 union에서 계산된 서버 값이며, 부분 셀 평균/합으로 재계산하지 않는다.
- 파일 내부에 필요한 원자료가 없는 비가산 집계는 **서버 확정값**으로 보존하고 조건 시트에 설명한다. 로컬에서 원신고까지 몰래 수집해 Excel 수식으로 복원하지 않는다.
- 신뢰된 앱이 생성한 수식만 작성한다. 수식 캐시/차트 numCache·strCache와 실제 셀 범위를 확인하고, 파일을 처음 열 때도 값과 그래프가 보여야 한다. Excel을 열어 수동 계산을 눌러야만 비로소 그래프가 나타나는 파일을 기본 성공으로 삼지 않는다.
- 날짜는 정렬 가능한 실제 날짜값/월 대표 날짜+적절한 서식을 사용하거나, 일정한 시간순 카테고리로 명시한다. 월 label을 문자열 사전순으로 잘못 정렬하지 않는다. KST 날짜를 UTC 변환하며 하루 밀리지 않게 한다.

### E07. 웹 차트를 Excel 객체로 매핑

ECharts option 전체를 `AddChart()`에 전달하는 것이 아니다. 공통 차트 의미 모델에서 Excel의 셀 범주·계열·값·축·범례로 매핑한다. 지원 기능은 고정 버전별 capability matrix로 기록한다.

| 웹 표현 | 엑셀 표현과 조건 |
|---|---|
| 월별 복수 처리결과 비율 | native 꺾은선. 선택 1~4지표 × 전체/내 신고 최대 8계열, 동일 지표색, 집단은 선 종류/marker/계열명으로 구분, 0~100% 축 |
| 월별 신고·답변 건수 | native 꺾은선. 각 계열의 원래 날짜 기준 유지, 비율과 임의로 한 축에 혼합하지 않음 |
| 기관·담당자별 비교 | native 가로/세로 막대. 긴 이름·소속은 읽을 수 있게, 합계 행을 개별 기관처럼 추가하지 않음 |
| 상호배타 처리결과·별점의 분포 | native 누적 막대. 100%는 정의된 원래 분모를 보존하고 전체·내 신고를 분리 |
| 처리기간·차량 반복일 등 이미 계산된 구간 분포 | 제공된 구간의 native 막대. 구간 원자료가 없는데 histogram을 재추정하지 않음 |
| 처리기간 × 과태료처분율 | native XY 산점도. X/Y 숫자와 단위 유지. 카테고리 선 차트로 대신하지 않음 |
| 기관 × 법규 또는 다른 교차표 | 셀 값과 조건부 색상 서식 히트맵. 비율은 고정 0~1 범위, 전체/내 신고는 같은 축 순서·색 척도 |
| 담당자 건수선 + 100% 처리결과 막대 | 지원되는 native 복합 차트·보조축으로 비율/건수 단위 분리. 실제 wrapper에서 보조축을 지원하지 않으면 아래의 의미 보존 규칙 적용 |
| 차원 없는 요약값 | 요약표. 의미 없는 native chart를 강제하지 않음 |

**100% 누적과 범례 숨김의 함정**

- 분석 분모를 바꾸지 않으면서 일부 계열만 내보내는 경우, Excel의 percent-stacked가 남은 계열을 새로 100%로 만들어 버리지 않게 한다.
- 필요한 경우 **원래 K/C/평가건수로 정규화한 셀을 일반 누적 막대로 그리고 축을 0~1로 고정**한다. 숨긴 계열 때문에 83.3%까지만 채워지는 것은 정상이며 그 의미를 설명한다.
- 모든 분할 계열을 넣는 경우에만 해당 버전 native percent-stacked를 사용해도 된다. 단, 원래 분모와 누락 사유를 계속 보존한다.
- 수용과 과태료, 전체와 내 신고처럼 겹치는 집합을 한 분할의 합으로 누적하지 않는다.

**히트맵**

- 조건부 색칠은 단순 셀 paint가 아니라 값 변경에 반응하는 Excel 조건부 서식으로 만든다.
- 0은 최소값 색, null/해당 조합 없음은 중립색 또는 빈 칸으로 구분한다. 색 척도를 유효 숫자 셀에만 적용한다.
- 전체/내 신고 비교는 교차표 두 개를 동일 행·열 순서로 배치한다. 퍼센트는 두 표 모두 0~1, 건수/금액은 두 집단 공통 최대값을 사용한다.
- XLSX에서 차트 객체를 만들 수 없는 히트맵이 조건부 서식 표인 것은 정상이다. ‘모든 내보내기에 chart XML이 반드시 존재’라는 잘못된 테스트를 만들지 않는다.

**보조축·세부 스타일이 wrapper에서 지원되지 않는 경우**

기본 line/bar/stack/scatter/셀 히트맵을 그림으로 대체하지 않는다. 복합 차트의 특정 보조축·선 스타일이 wrapper에서 빠졌다면 먼저 공식 기능·최소 Excelize bridge로 보완한다. 그래도 지원되지 않는 복합 조합은 **같은 sheet에 같은 범주 축의 native 비율 차트와 native 건수 차트를 분리 배치**하는 의미 보존 방식을 사용할 수 있다. 사용자 안내와 조건 시트에 차이를 명시하고, 같은 단위 한 축인 것처럼 왜곡하지 않는다. 이 경우를 완전 동일 복합차트 PASS로 기록하지 않는다.

스크린샷 이미지는 사용자가 별도 요청한 부가 참고물일 때만 가능하며 native 기본 차트를 대체하지 않는다. 이번 작업에 지도 타일/광고/카카오 로고까지 캡처하는 기능은 추가하지 않는다.

### E08. 다운로드·로딩·취소·자원 수명

기존 활동 표시 체계를 재사용하되 DB 조회와 파일 생성을 구별한다.

권장 단계: `엑셀 기능 준비 중 → 통계표 작성 중 → 차트 작성 중 → 파일 저장 준비 완료`. 실제 계산 가능한 작업 수가 없으면 가짜 70%/99%를 만들지 않는다. HTTP가 끝났다고 파일 완성으로 처리하지 않는다.

- 한 번에 하나의 export job을 기본으로 하고 버튼 중복 클릭은 병합/비활성화한다. `jobId + viewerGeneration + snapshotKey`로 late 메시지를 검증한다.
- 처음 WASM 다운로드 중 실패, 초기화 실패, unsupported browser, Worker 종료, 메모리 부족, 쓰기 오류, 잘못된 XLSX 결과를 서로 구분한 메시지와 재시도를 제공한다. 이 오류로 지도/대시보드 정상 데이터를 지우지 않는다.
- 취소 버튼은 현재 export만 중단한다. 관련 없는 통계 조회 상태를 끄지 않는다. Web Worker의 긴 동기 WASM 작업 취소가 메시지로 즉시 불가능하면 worker terminate 후 다음 요청에서 새로 초기화하는 방식으로 구현한다.
- 계정 전환/로그아웃 후에는 이전 export buffer·파일 저장 버튼·작업별 라벨을 폐기한다. 같은 계정에서 결과 조건만 바뀐 경우는 E04의 고정 snapshot 규칙을 따른다.
- buffer의 실제 타입을 확인해 Uint8Array/ArrayBuffer/Blob으로 변환한다. 기본 MIME은 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`다.
- `URL.createObjectURL()` 사용 후 브라우저 다운로드가 시작될 시간을 고려해 revoke하고, anchor·작업 버퍼·workbook 핸들을 정리한다. 빈 파일이나 stringified buffer를 저장하지 않는다.
- 생성 시간이 길어 브라우저의 사용자 활성 조건이 사라졌을 때는 완성된 파일에 대한 명시적 `파일 저장` 버튼을 제공할 수 있다. 이때 파일을 다시 계산할 필요는 없다. 브라우저 기본 보안 다운로드 경고를 무력화하지 않는다.
- reusable Worker/런타임이면 각 workbook Close/동등 해제 경로를 확인한다. Go 메모리가 매번 즉시 줄어든다고 가정하지 말고 최대치·반복 증가를 측정하고 필요한 idle worker 정리를 한다.
- 목표 결과 최대치에서 시간·메모리·파일 크기를 측정한다. 너무 큰 차트는 그래프 분할/명시적 대상 축소를 안내한다. 임의로 뒤쪽 행·계열을 버리지 않는다. 사용자 동의 없는 ‘표만’ downgrade는 금지한다.
- 데이터가 이미 완전하면 파일 생성만으로 API를 재호출하지 않는다. 정적 WASM 다운로드 네트워크와 통계 API 요청을 테스트에서 구분한다.
- 생성된 사용자 XLSX를 GitHub Actions artifact, Supabase Storage, 로그·분석 도구로 업로드하지 않는다. CI에서는 합성 예제만 저장한다.

### E09. 파일 보안·일관성

- 사용자가 볼 수 있는 집계와 라벨만 workbook에 넣는다. 보조 시트·문서 속성·custom properties·차트 cache에도 원 번호, user id/hash, token, 비공개 이벤트가 없어야 한다.
- 텍스트 값이 `=`, `+`, `-`, `@`, 탭/제어문자로 시작해도 수식으로 실행되지 않도록 명시적 문자열 쓰기 API와 서식을 사용한다. 신뢰된 수식 생성 경로는 별도로 제한한다. 정상 숫자 타입의 음수를 무조건 문자열로 변환하지 않는다.
- 이름·기관·법규·주소·sheet label에 따옴표/한글/괄호가 있어도 chart reference와 Excel formula를 올바르게 escape한다.
- 외부 workbook reference, DDE, 자동 실행 수식, 매크로, 링크된 외부 이미지, 로그인 URL/JWT가 들어가는 하이퍼링크를 생성하지 않는다. 내부 셀/시트 참조만 기본 허용한다.
- 승인된 주소의 사용자 직접 XLSX 다운로드와 F02의 공용 recipe 링크 정책은 구분한다. 다운로드한 집계 파일을 사용자가 외부에 재전달할 수 있다는 점은 안내하되 이미 동의로 공개된 이름·주소를 임의 마스킹/삭제하지 않는다. 원본 비공개 컬럼을 새로 공개하지도 않는다.
- `filter_members.status=unconfirmed`인 대상의 이름·미공개 상세를 저장된 과거 labels에서 부활시키지 않는다. 확인 불가 상태와 제외 수만 현재 응답의 허용 정보로 적는다.
- runtime export 모듈은 프런트/Worker 전용으로 둔다. server/Edge 공용 domain이 Excelize loader·browser API를 runtime import하지 않게 하고 Deno 경로 회귀를 검사한다.

### E11. 최소 회귀·산출물 검증

동봉 `ACCEPTANCE_TESTS.md`의 EX 항목은 이번 추가 범위다. 기존 F01~F05 검사도 유지한다.

1. **실제 브라우저의 Excelize WASM**으로 합성 fixture XLSX를 생성한다. Node 전용 생성이나 다른 라이브러리로 만든 샘플로 브라우저 성공을 대신하지 않는다.
2. ZIP 무결성뿐 아니라 `[Content_Types].xml`, workbook/worksheets/styles/relationships, `xl/charts/chart*.xml`과 worksheet drawing reference를 검사한다. native 차트용 `numRef/strRef`·셀 범위·계열 개수·값·gap·축·색 척도를 확인한다.
3. 히트맵 전용 출력은 숫자 셀과 `conditionalFormatting`을 검사하고, 비교 표의 양쪽 축/범위가 같아야 한다.
4. G fixture의 66.666…/16.666…/16.666…/40/25%와 1/1+9/99=10%를 확인한다. `차트 데이터` 셀은 비율 0~1, 표와 chart cache가 같은 값이어야 한다.
5. 월별 4지표/내 비교 8계열, native bar/stack/scatter, 전체/내 비교 히트맵, 표시 계열 숨김과 100%분모, 빈 달·실제 0·1건을 확인한다.
6. 완전 결과 다운로드에 통계 API 재요청이 없는지, 최초 사이트 방문에 WASM 요청이 없는지, COOP/COEP/SAB 없이 동작하는지 Network로 확인한다.
7. 생성 중 취소·P1→P2 또는 query 변경·A→B 계정 교체·오류 재시도·반복 10회 생성에서 오래된 파일 저장/자원 누수가 없어야 한다.
8. 파일 크기>0, 확장자, 시트 이름, 차트 객체 존재 여부만 검사하고 완료하지 않는다. Excel에서 차트 원본 범위가 편집 가능하고, 해당 원본 셀 수정→차트 변화가 있는지 확인한다.
9. Microsoft Excel에서 ‘복구된 레코드/읽을 수 없는 내용’ 경고 없이 열리는지, 숫자·차트·조건부 서식·한글 이름·조건 시트가 읽히는지 검사한다. Excel Desktop/Excel Web 등 실제 검증한 제품·버전을 기록한다. 다른 뷰어 검사는 보조 증거이며 Excel 확인의 대체라고 적지 않는다.
10. 실제 Excel을 실행할 수 없는 환경이면 OOXML/재읽기 검증 결과와 **Excel 실사용 BLOCKED**를 분리한다. 캡처나 실제 셀 편집을 하지 않았는데 완료로 보고하지 않는다.

합성 fixture의 기대값은 구현 출력으로 바꾸지 않는다. 생성된 예제 파일과 검사 보고는 production bundle에서 제외한다. 라이브러리의 허용된 WASM 정적 자산을 배포하려고 기존 민감정보/dist 스캔 전체를 비활성화하지 않는다.

### E12. 완료 기준

F06은 `xlsx 생성`, `차트 이미지 삽입`만으로 완료가 아니다. **native 셀 연결 차트/조건부 서식, 정확한 전체/내 수치·분모, 전체 결과 범위, 비격리 lazy 로딩, 취소·계정 경계, 실제 파일 검증**까지 필요하다.

새 기능에서 지원하지 않는 표현은 문서와 UI에 구분한다. 기본 지원 차트가 빠진 상태를 완료로 선언하지 않는다. 이전 F01~F05와 새 F06은 모두 최종 코드 SHA에서 재검증한다. XLSX 기능 도입을 이유로 기존 공유 링크·범례·계정 분리·로딩 표시·핀 선택·스크롤·장기 조회의 마감을 생략하지 않는다.
