## 2. 합성 자료

동봉 `fixtures/export-oracle.json`은 **독립 기대값 예시**다. 실제 서버 응답을 대체하지 않고, 구현 결과를 다시 expected에 복사하지 않는다. 구현자가 현재 타입의 synthetic fixture로 adapter를 작성한다.

핵심 사례:
- G: C=20, A=12, P=3, R=3, U=2, K=18, F=8, W=5.
- 가중 합계: A지역 1/1, B지역 9/99 → 10/100=10%.
- 월 M1 유효 비율, M2 답변 0이라 비율 null, M3 답변 2건 모두 불수용이라 수용/과태료는 실제 0%.
- 전체 셀 50%(1/2), 내 신고 셀 100%(1/1), 다른 셀에는 내 신고 없음.
- 공개 평가 [1,1,3,5,5,5] → 6건, 점수합20, 평균20/6. 비공개/미평가를 0으로 넣지 않음.
- 숨긴 불수용 계열: G의 수용+일부 막대 높이는 5/6이고, 원래 K는18로 유지.
- 서로 다른 기관의 동명이인, 긴 한글명, 따옴표가 있는 라벨, 1건·0건·누락·확인 불가 대상.

## 5. 실행 증거

검사 환경을 `unit`, `browser-wasm`, `xlsx-ooxml`, `excel-desktop`, `excel-web`, `edge-runtime`, `real-sdk`, `production` 등으로 구분한다. Excelize WASM 산출물을 다른 라이브러리로 대체 생성해 통과시키지 않는다. XML 검사 도구와 생성 엔진은 다른 역할이다.

검증용 Excel 파일은 합성 데이터만 사용하고 production에 포함하지 않는다. 실제 사용자 집계 파일·토큰을 커밋하지 않는다. 실제 Excel이 없는 환경이면 OOXML 검사는 진행하고 Excel 직접 검사는 BLOCKED로 분리한다. 브라우저 기본 보안 경고와 ‘읽을 수 없는 내용/복구된 레코드’ 경고도 구분한다.

|---|---|---|---|---|---|---|
| EX-01 | NOT_RUN | | browser-wasm | | | |

최종 보고의 F01~F06과 이 테스트 ID를 매핑한다. 테스트 하나가 관찰만 했는지 실제 assertion인지 구별하고, 기능 assertion 없이 ‘콘솔 오류 없음’만으로 기능을 PASS 처리하지 않는다.
