# safetyreport-community-map 구현 지시서
## 승인 시안 적용 · 주소별 지도 · 신규 분석 6종 · 사용자 불편 10종 해결

이 문서는 검토 의견이 아니라 실제 구현 지시다. 계획만 제출하고 끝내지 말고, 코드·테스트·문서·브라우저 검수까지 진행하라. 운영 환경에 대한 별도 권한이 없는 경우에도 로컬에서 가능한 구현과 검증을 완료하고, 운영 적용만 분리해서 보고하라.

---

## 0. 목표, 참고 자료, 우선순위

대상 저장소는 `Fentanest/safetyreport-community-map`이다. 작업 시작 시 현재 브랜치·HEAD·미커밋 변경을 확인한다. 사전 검토 기준은 `9eb3694e6fb95db3031fa7b7b64d2ade4674258e`지만, 작업 시점의 변경을 먼저 대조하고 최신 코드를 과거 버전으로 덮어쓰지 않는다.

함께 제공한 자료:
- `references/approved-dashboard.png`: 사용자가 승인한 대시보드 배치·밀도·시각적 계층의 기준.
- `references/current-dashboard.png`: 변경 전 전체 페이지와 기존 기능 확인용.
- `ACCEPTANCE_TESTS.md`: 필수 재현·회귀·시각 검수 기준.

이번 목표는 다음을 한 번에 연결하는 것이다.
1. 승인 시안처럼 지도 + 조밀한 요약 영역 + 중간 크기 분석 카드 + 짧은 표 영역으로 재배치한다.
2. 아래 R01~R10을 전부 해결한다. 글자만 바꾸거나 CSS만 바꿔서 끝내지 않는다.
3. 신규 분석 A01~A06을 실제 서버 집계와 API로 구현한다. 이미지에 보이는 4종 외에 앞서 논의한 산점도와 별점 분포까지 포함한다.
4. 기존 조회·필터·개인 비교·접근 제한·마스킹·정확한 통계 정의를 유지한다.

우선순위는 **이번 명시적 사용자 요구 > 승인 시안의 구조 > 최신 제품 규칙 > 기존 구현**이다. 이미지의 예시 숫자·차량번호·기관명·법규 설명·날짜·메달·문구는 데이터 명세가 아니다. 이를 실데이터나 사실처럼 하드코딩하지 않는다. 시안에 표시된 수치가 기존 화면과 달라도 실제 API 값을 사용한다. 특히 장소 수와 참여자 수를 혼동하지 않는다.

기존 라이트/다크 토큰과 브랜드를 재사용한다. 시안의 톤은 반영하되 새로운 팔레트를 통째로 도입하지 않는다. 실제 카카오 지도에서 지원하지 않는 가짜 다크 베이스맵을 만들거나 지도의 출처·로고까지 CSS 반전하지 않는다. 시안 전체를 이미지로 붙이는 구현은 금지한다.

## 1. 작업 시작과 협업

먼저 `AGENTS.md`, `PROJECT_RULES.md`, `SOL.md`, `MUSE.md`, `docs/implementation/MASTER_PROMPT.md`, `docs/product-decisions.md`, `docs/ui-spec.md`, `docs/screen-by-screen.md`, 최신 API·지표·개인 비교 문서를 읽는다. 관련 `.agents/skills/`도 읽는다. 이 문서와 충돌하는 과거 UI 명세는 이번 요구에 맞게 갱신한다.

현행 저장소 규칙대로 Sol이 계약·서버·보안·통합을 맡고, Muse가 UI 공동 구현과 실제 브라우저 검수를 맡는다. 호스트에 제공된 정확한 모델·호출 경로를 확인한다. 다른 프로젝트의 에이전트 체계를 가져오지 않는다. 같은 파일 동시 수정 금지, 계약·토큰·package/lock은 single writer로 관리한다. 도구가 제공되지 않으면 실제 호출한 것처럼 보고하지 않는다.

기본 작업 범위는 이 저장소의 코드·로컬 SQL 마이그레이션·테스트·문서다. 다른 저장소, 운영 SQL, 클라우드 설정, push/release/실제 배포는 기존 승인 절차를 지킨다. 새로운 원천정보가 정말 필요한 경우에만 upstream 계약 변경안을 별도로 낸다. 이번 핵심 기능을 위해 신고 본문·처리답변 원문·사진·첨부파일의 추가 업로드를 요구하지 않는다.

### 사전 코드 대조에서 확인한 사항

- `Dashboard.tsx`는 scope 변경 때마다 `loadState='loading'`으로 바꾸고, 본문은 `loadState==='ready' && data` 아래에 있다. 따라서 갱신 중 지도와 차트가 제거됐다가 다시 만들어질 수 있다. 브라우저 문서 자체의 reload인지, 이 재마운트로 인한 체감 새로고침인지 Network와 마운트 로그로 구별하여 검증한다.
- `MapPanel.tsx`는 idle 뒤 300ms에 범위를 적용한다. 지도 재생성·초기 idle·범위 적용이 연결되면 반복 요청의 원인이 될 수 있다. 이미 AbortController가 있다고 해결된 것으로 판단하지 않는다.
- `loadDashboard()`는 매번 `meta → dashboard`를 읽고, 기관 목록과 내 신고 비교도 별도로 읽는다. 새로운 차트 6개를 각각 같은 원천을 읽는 별도 요청으로 붙이면 요청 폭증을 악화시킨다.
- `MapPanel.metricValue()`가 반환하는 비율은 0~100인데 `markerDataUrl()`은 0~1 정도의 값으로 clamp한다. 지표를 바꿔도 색이 비슷하게 고정되는 직접적인 원인이 될 수 있다. 클러스터도 비율을 단순 평균한 뒤 건수 최대값으로 나누고 있어 단위가 맞지 않는다.
- 지도 경계 색은 현재 지표가 아니라 `report_count`로 계산된다. 마커만 수정하고 경계·hover·범례는 그대로 두지 않는다.
- `FilterDrawer`의 포커스 effect 의존성에 `p.onClose`가 있고, Dashboard는 `onClose={() => setDrawer(false)}`를 전달한다. 입력 변경에 따른 부모 렌더마다 함수 참조가 달라져 cleanup/focus가 반복되는 경로가 있다.
- `EntityTable`의 기관/담당자 전환은 헤더 오른쪽에 있다. `열 선택`은 현재 실제 열 체크박스가 아니라 안내문만 보여준다.
- `PublicPoint`에는 `warning_count`가 없다. 기존 `/points/{key}`는 점 요약만 반환하며 장소에 한정한 기관·담당자 전체 목록을 제공하지 않는다.
- `pointRows()`는 `point_key`로 묶고, `mapNodes()`는 1,000개 초과 시 서버에서 다시 공간 집계한다. 주소 핀 변경은 UI뿐 아니라 이 두 계층과 상세 조회를 함께 수정해야 한다.

위 사항은 구현 시작점이지 실행 검증의 대체가 아니다. 변경 전 재현·원인·수정·검증 결과를 남겨라.

## 3. 승인 시안을 구현할 레이아웃

### 3.1 전체 구조

데스크톱은 좌측 nav rail, 작은 상단바, 한 줄 중심의 조건바, 12열 콘텐츠 그리드로 구성한다. 콘텐츠는 화면 폭을 충분히 사용한다. 과도하게 좁은 고정 max-width, 카드 높이를 맞추기 위한 빈 공간, 몇 줄짜리 결과를 담은 거대한 박스를 없앤다.

기본 ‘지도+통계’ 배치:

```text
[상단바 / 제목 / 공통 날짜·분류·법규·상세 필터·내 신고 비교·보기 방식]
[명확한 적용 조건 칩과 개별 해제 / 필요할 때만 노출]

[지도 7열: 약 520~640px] [요약 5열: KPI + 추가 지표 + 개인 비교]
                         [핀 선택 시 같은 우측 영역에 장소 상세]

[월별 추이: 건수/처리결과 비율] [답변 소요기간 분포]
[기관 × 법규 히트맵]            [차량별 반복 신고일 분포]
[처리기간 × 결과 산점도]        [처리결과별 별점 분포]

[지역별 현황: 짧은 표]          [많이 신고된 차량 TOP5: 짧은 표]
[위반법규 현황: 요약 표]        [기관·담당자 결과: 요약 표]

[필요 시 표의 확장 보기 / 간결한 이용 안내 / footer]
```

- 카드 gap은 기본 16~20px, 내부 padding은 16~20px 정도를 출발점으로 실제 화면에서 조정한다.
- 지도는 첫 화면의 중심이되 시안 이미지처럼 필요 이상으로 세로로 늘리지 않는다. 오른쪽 요약과 균형을 맞춘다.
- 주요 KPI는 기본 2열×4개를 중심으로 구성한다. 기존 신고·답변완료·수용·일부수용·불수용·과태료·기간·참여자 정보를 보존한다. 금액·별점·장소 수 등 나머지 지표도 작은 추가 요약이나 상세 비교에서 빠짐없이 접근할 수 있게 한다.
- 개인 비교는 동일 scope/version의 전체와 내 신고를 나란히 보여준다. 같은 수치를 여러 거대 카드에 중복하지 않는다. 필요할 때 상세 비교를 펼친다.
- 기존 `OutcomeCard`의 결과 비율은 조밀한 결과 막대/요약으로 보존한다. TOP5 높이에 맞춘 큰 빈 박스로 남겨두지 않는다.
- 기존 월별 신고·답변 건수 그래프는 삭제하지 않는다. 신규 월별 비율과 같은 카드의 ‘건수 / 처리결과 비율’ 보기로 통합한다. 장소 패널의 탭 제거 요청을 모든 차트 보기 전환 제거로 확대 해석하지 않는다.
- 두 하단 표는 기본 5~8행 정도의 요약 밀도로 시작하고 검색·페이지·전체 보기로 확장한다. 컬럼 수가 많은 상세 표를 반폭에 억지로 넣어 글씨를 축소하지 않는다. 확장 보기에서만 전체 폭 또는 큰 패널을 사용한다.
- 표·카드에 `min-width:0`, 넘침 처리, 고정 숫자 정렬을 적용한다. 기관명·주소는 필요한 만큼 줄바꿈한다.
- 모바일은 한 열, 지도 다음 요약과 분석 순서로 배치한다. 390px에서 가로 페이지 스크롤이 없어야 한다. 표 내부 스크롤은 허용하되 기관/담당자 전환·검색은 화면 밖으로 밀리지 않는다.
- 다크·라이트·시스템 테마, 기존 지도/통계/함께 보기, 브리핑 모드, 키보드 접근성을 보존한다.
- 보기 변경으로 React 트리에서 지도를 다른 부모 아래 재삽입하지 않는다. 안정된 단일 지도 host와 CSS grid area/표시 상태로 배치를 변경한다.

### 3.2 시안에서 복제하지 말아야 할 것

예시 원본 차량번호, 사실 확인되지 않은 기관/법규 조합, 장식용 가짜 sparkline·증감률, 실제로 없는 공지/고객센터/알림 기능, 순위 메달을 복제하지 않는다. 시안은 레이아웃과 비례를 참고한다. 데이터가 없으면 ‘자료 없음’, 공개되지 않는 값이면 해당 사유, 값이 0이면 0으로 구분한다. ‘운영 포인트’, 자동 평가, 장문의 인사이트 박스를 새로 만들지 않는다.

## 4. 사용자 요구 R01~R10

### R01. 지도 장소 필터 탭 삭제

지도 내부의 `내 신고가 있는 곳`, `함께 신고한 곳`, `관심 지역` 탭 버튼을 제거한다. 다른 선택지가 없어지는 `전체`만 홀로 남기지 말고 해당 탭 행 자체를 제거한다. 관련 사용법·활성 조건 안내도 제거한다.

`pointFilter` 상태, `filterPoints()` 적용, 관련 props와 과거 저장/URL 값이 보이지 않는 필터로 남아 핀을 제한하지 않게 정리한다. 현재 지도에는 적용된 공통 필터에 맞는 모든 장소가 보여야 한다.

단, 상단 `내 신고와 비교`, 본인 계정 식별, 필요한 개인 비교 데이터까지 삭제하지 않는다. 지역 목록의 관심 설정을 이 요구만으로 임의 삭제하지 않는다. 개인 표식은 유지할 수 있으나 탭과 중복 범례를 되살리지 말고 혼잡하면 간결한 툴팁/선택 장소 표시로 옮긴다.

### R02. ‘보이는 지역만 보기’ 버튼 삭제

지도 위의 `보이는 지역만 보기` 수동 버튼과 공간을 삭제한다. 같은 기능을 다른 이름의 수동 버튼으로 재생성하지 않는다.

지도의 범위 정보 자체, 확대/축소, 전국 보기, 지역 경계 클릭, R04 자동 갱신은 유지한다. 자동 범위가 적용되어 있을 때 이를 알리는 조건 칩은 유지하되 버튼 복제품이 아니라 현재 상태 표시와 해제 용도로만 사용한다.

### R03. 지도 지표 수정과 실제 동작

버튼을 정확히 `신고 수 / 수용률 / 불수용률 / 과태료`로 바꾼다. `MapMetric`의 partial을 rejection으로 바꾸고 상태·전달·마커·클러스터·경계·범례·hover·목록 대체화면·테스트를 연결한다. 다른 KPI나 결과 표의 일부수용 정보는 삭제하지 않는다.

지표 정의:
- 신고 수: 현행 신고량 정의에 맞는 건수. 기본 날짜 기준을 임의 변경하지 않는다.
- 수용률: `accepted / result_known × 100`.
- 불수용률: `rejected / result_known × 100`.
- 과태료: 현행 지도 의미인 과태료 부과율, `fine_count / completed_count × 100`. 버튼은 ‘과태료’, 범례/tooltip은 ‘과태료 부과율’로 명시한다. 금액이나 수용률로 잘못 배선하지 않는다.

렌더링 원칙:
1. 신고 수는 핀 숫자에 건수, 비율 지표는 핀에 퍼센트를 표시하여 클릭 결과가 눈에 보이게 한다. 표본 건수는 tooltip/상세에 함께 표시한다.
2. 색상 함수 입력은 별도의 0~1 스칼라로 표준화한다. 퍼센트의 화면값 90.1과 색상값 0.901을 섞지 않는다. 건수는 정의된 scale로 정규화한다.
3. 비율은 0~100% 고정 범례를 쓴다. 실제 0%와 분모 없음(null)의 색·표시를 구분한다. null에 건수 색을 대입하지 않는다.
4. 공간 클러스터의 비율은 구성 장소의 **분자 합/분모 합**이다. 비율 단순 평균이나 최대 건수로 나누는 연산을 금지한다. 백엔드 `mapNodes()`와 프론트 `clusterPoints()` 양쪽에 적용한다.
5. `KakaoPointInput` 등에 필요한 분자·분모·표시 문자열·색상값을 분리한다. 실제 지도 지표 변경에서 재조회·지도 재생성은 필요하지 않게 한다.
6. 지역 경계의 fill·hover·범례도 선택 지표를 따른다. 데이터가 있는 마커와 경계 모두 10%, 50%, 90% fixture에서 구분되어야 한다.
7. ‘신고 수 0, 해당 기간 답변은 있음’과 ‘비율 0%, 분모는 있음’을 혼동해 제거하지 않는다.

### R04. 지도 이동 시 전체 새로고침·요청 폭증 제거

사용자는 자동 통계 변경을 켜고 지도를 반복 이동할 때 화면 전체가 새로고침되는 것처럼 보이고 결국 통계 조회가 실패한다고 보고했다. debounce 숫자 하나만 키워 해결했다고 하지 않는다.

상태를 분리한다:
- `draftFilters`: 입력 중인 값.
- `requestedScope`: 새로 적용/요청한 조건.
- `displayedData + displayedScope + datasetVersion`: 마지막 성공한 화면 묶음.
- `viewport`: 지도 자체의 현재 bounds/zoom.
- `selection`: 선택한 주소 장소.
- `isInitialLoading`, `isRefreshing`, `refreshError`: 최초 로드와 부분 갱신 상태.

구현:
1. 기존 성공 데이터가 있을 때 부분 갱신을 이유로 지도·본문·차트를 unmount하지 않는다. 작은 갱신 표시만 사용하고 지도 중심·줌·스크롤을 유지한다.
2. 이전 데이터 유지 중에는 그 데이터의 실제 scope/version을 표시한다. 요청 조건과 이전 수치를 섞어 새 결과처럼 보이지 않게 한다. 정상 응답이 오면 의존 지표를 일관된 버전으로 교체한다.
3. drag/bounds_changed마다 호출하지 말고 사용자 이동 종료 idle를 모은다. trailing debounce는 약 500ms를 시작값으로 하며, 별도의 최소 갱신 간격과 서버 요청 예산을 둔다. 예산·간격은 실제 rate limit과 한 번의 갱신에 필요한 요청 수를 확인해 조정한다.
4. 동일 bounds 또는 표시상 변화가 없는 subpixel 이동은 새로운 요청을 만들지 않는다. 비교용 정규화가 원천 좌표 저장값을 변경해서는 안 된다.
5. 지도 생성·`fitBounds`·`relayout`·응답 반영으로 발생한 프로그램 이동과 사용자 이동을 구분한다. 초기 idle 및 응답 반영이 다시 scope 갱신을 호출하는 순환을 끊는다.
6. 자동 갱신은 최신 target만 남긴다. 같은 resource/scope/version의 중복 요청은 합치고, 이전 응답은 request generation으로 무시한다. 취소된 요청을 사용자 오류로 표시하지 않는다. 클라이언트 취소만으로 이미 시작된 서버 집계 비용이 사라진다고 가정하지 않는다.
7. 매 이동마다 meta를 재요청하지 않는다. 유효한 metadata/version은 현재 로그인 세션 메모리에서 재사용하고, 서버의 버전 확인은 유지한다. 409이면 metadata를 한 번 새로 읽고 최신 범위만 제한적으로 재시도한다.
8. 신규 6개 차트는 같은 facts/선택 집합으로 한 번에 집계한다. 카드마다 동일 전체 집계 RPC를 각각 호출하지 않는다. dashboard 응답 확장 또는 묶음 analytics 응답을 사용한다. 화면 밖 기관표는 불필요하게 매번 재조회하지 않는다.
9. 429는 `Retry-After`를 준수한다. 그동안 자동 요청을 멈추고 마지막 정상 화면을 유지한다. 이동은 최신 범위만 기록하고 대기 종료 후 그 범위만 재시도한다. 네트워크/5xx도 제한된 retry와 명확한 상태로 처리한다. rate limit을 끄거나 무제한 상향하는 해결은 금지한다.
10. 401/403, 로그아웃·계정 변경·동의 철회·열람 자격 상실은 이전 화면 유지 예외다. 모든 관련 조회를 취소하고 기존 공개/개인 데이터 캐시를 비우며 접근 게이트로 전환한다. refresh token 갱신은 single-flight로 하고 자동 로그인 재시작 금지를 보존한다.
11. 자동 이동에 따른 URL 갱신은 필요한 경우 `replaceState`로 처리하여 history를 도배하지 않는다. 명시적 필터 선택은 `pushState`를 사용할 수 있다. `location.reload/assign`, 폼 navigation을 쓰지 않는다.
12. 지도/통계 보기 전환·핀 선택·지표 변경은 전체 조회를 다시 시작하지 않는다. 지도는 안정된 단일 host로 유지한다. 컨테이너 크기는 ResizeObserver 등으로 측정하여 지도 relayout과 차트 resize만 수행한다.

필터 결합 규칙:
- 지역 목록에서 지역 선택: 이전 자동 bbox를 해제하고 선택 지역으로 이동한다. 이 프로그램 이동으로 자동 bbox를 즉시 재삽입하지 않는다.
- 그 뒤 실제 사용자가 이동: 자동 갱신 ON일 때 공통 조건과 새 viewport를 명확히 결합한다. 지역 조건이 남아 있다면 화면에 둘 다 표시한다.
- 자동 갱신 OFF: 대기 중 자동 요청을 취소하고 새 지도 이동으로 통계 조건을 바꾸지 않는다. 마지막 적용 bbox는 명확한 칩으로 남겨 해제할 수 있게 한다.
- 조건 전체 초기화: region/bbox/선택 장소/대기 자동 요청을 정리하고 전국으로 돌아간다.

### R05. 장소 상세 탭 제거, 한 번에 나열

주소 핀을 클릭했을 때 오른쪽 상세 패널에서 `안내 / 처리 결과 / 기관·담당자` 탭을 제거한다. 세 영역을 한 패널에 연속 배치한다. 모든 영역을 보려면 다시 눌러야 하는 accordion으로 대체하지 않는다.

권장 순서:
1. 주소 제목·주소 복사·닫기.
2. 신고 건수, 계도 건수, 과태료 건수, 수용률/불수용률 등의 짧은 요약.
3. 수용/일부수용/불수용/결과 미상 분포와 실제 분모.
4. 그 주소 신고를 처리한 기관 목록과 기관별 수치.
5. 그 주소 신고를 처리한 담당자 목록과 소속 기관·수치.
6. 필요한 최소 이용 설명.

기존 선택 장소에서 기관·담당자가 비어 있는 경로를 수정한다. 전국 기관 목록의 상위 몇 개를 장소 결과인 것처럼 쓰지 않는다. 같은 `place_key`에 속한 건별 자료를 현재 필터와 함께 서버에서 집계한다.

핀 선택은 전역 필터 변경과 분리한다. 화면 전체 재조회 대신 장소 상세 요청만 수행하고, 빠르게 A→B를 누르면 A 응답은 B를 덮어쓰지 못한다. 선택 상태는 `place_key`로 유지한다. 선택 장소가 새 필터에 없을 때 이유와 함께 선택을 정리한다.

데스크톱은 기존 우측 영역 안에서 읽고 닫을 수 있게 하며 지도를 재마운트하지 않는다. 모바일에서는 지도 아래 인라인 상세 또는 하나의 스크롤 가능한 패널로 모든 섹션을 제공한다. 긴 기관/담당자 목록은 리스트의 페이지/더보기만 허용한다. 탭은 다시 만들지 않는다.

### R06. 장소 정보 ‘답변 완료 건수’를 ‘계도 건수’로 변경

**장소 패널의 요약 항목**에서 답변 완료 건수를 계도 건수로 교체한다. 전역 답변완료 KPI나 통계 계산용 `completed_count`를 삭제하는 요구가 아니다.

현재 DTO에서 경고 처분은 `disposition='warning'`이다. 계약·파서의 계도/경고 매핑을 확인하고 확인된 warning 계열만 계도로 집계한다. 범칙금(`penalty`), 미확인, 단순 불수용을 계도에 합치지 않는다. 원천에서 계도가 미확인으로 손실된 경우 임의 복원하지 않고 필요 변경을 보고한다.

`warning_count`를 주소별 장소 집계, 서버 공간 클러스터, 장소 상세, PublicPoint/새 PlaceSummary, JSON 검증 스키마, client adapter, fixture, 개인 비교가 필요한 지점까지 연결한다. 기존 서버가 필드를 주지 않는 경우 0으로 채워 ‘계도 없음’으로 표시하지 않는다. 지원/미지원 또는 null을 구분한다.

화면 라벨은 ‘계도’, tooltip에는 ‘경고·계도 처분으로 확인된 신고’를 사용한다. 분모와 대상은 같은 기간의 답변 완료 집합을 따른다.

### R07. 주소 기반 핀과 주소 중심 상세

목적은 같은 주소의 좌표가 조금씩 달라 ‘1’ 핀이 과도하게 생기는 문제를 해결하는 것이다. 핀의 **장소 식별·그룹 기준을 주소로 바꾼다.** 지도에 좌표를 전혀 쓰지 않는다는 뜻이 아니라 주소 그룹당 대표 위치 하나를 쓰라는 뜻이다.

#### 주소 식별
- 원래 주소·정확 좌표·신고 식별키는 그대로 보존한다. 화면 묶음을 위해 원천을 덮어쓰지 않는다.
- `normalizeAddress` → `place_key`를 서버 공통 경로에서 생성한다. 같은 주소면 업로더·dataset·조회 순서가 달라도 같은 장소로 연결된다.
- 공백·제어문자·확인된 시도 표기 변형은 정리할 수 있다. 전국 범위의 전체 주소를 사용하고 시군구·도로명·건물번호/본번·부번·산 여부 같은 구별 정보를 유지한다.
- `10`과 `10-1`, 이름이 같은 타 시군구 도로, 서로 다른 건물/지번을 무리하게 합치지 않는다. 도로명↔지번의 동일성은 검증된 주소 식별/캐시가 있을 때만 연결한다. 동·호수 같은 상세 항목도 합칠 기준 없이 무조건 잘라내지 않는다.
- 모든 주소 미상 건을 단일 핀으로 모으지 않는다. 주소 미상은 통계와 ‘주소 미확인’ 목록/건수에 보존하되 지도 위도경도별 1핀으로 되돌리지 않는다.

#### 대표 위치
- 이미 보유한 유효 원본 좌표 중 결정적인 규칙으로 대표점을 선정하여 재사용한다. 필터·정렬이 바뀔 때마다 배열 첫 요소가 대표점이 되는 구현은 금지한다. 필요하면 주소 차원/대표점 테이블을 둔다.
- 확인된 주소 geocoding 좌표가 기존 시스템에 있다면 재사용할 수 있다. 주소별 캐시를 두고 API 호출은 서버/사전 작업에서 한다. 매 렌더링·지도 이동·조회마다 주소 개수만큼 외부 geocoding을 호출하지 않는다.
- 새 주소 API 키를 모든 핵심 작업의 필수 전제로 만들지 않는다. 유효 좌표가 하나도 없는 주소는 통계·목록에 보존하고 지도 미표시 사유를 안내한다. 임의의 전국 중심이나 (0,0)에 찍지 않는다.
- 대표점은 표시용임을 데이터 타입과 문서에 구분한다. 원래 좌표를 반올림·격자화해 재저장하지 않는다.

#### 통계와 클러스터
- 원천 신고 식별에 따른 중복 제거를 먼저 적용한다. 같은 주소의 다른 신고들은 모두 건수에 포함하고 핀만 1개로 묶는다.
- 현행 행정경계·bbox 필터는 원천 신고 위치로 판단한 후 주소 그룹을 만든다. 주소 대표점이 다른 경계에 있다는 이유로 소속 지역 통계를 옮기지 않는다.
- 표시 대표점이 화면 밖인데 해당 주소의 선택된 원천은 화면 안인 경계 사례를 다룬다. 필요한 경우 선택된 원천 중 화면 안 대표점을 ‘표시용 대안’으로 선택하되 원천/기본 대표값은 바꾸지 않는다. 지도에 보이는 장소와 선택된 통계의 차이를 숨기지 않는다.
- 충분히 확대하면 주소당 1핀이다. 축소 시에는 주소 핀끼리 시각적 클러스터로 묶는다. 서로 다른 주소의 묶음을 단일 주소라고 표시하지 않는다.
- 서버의 1,000개 상한 집계와 클라이언트 클러스터를 모두 점검한다. 서버에서 압축한 집계점을 클라이언트 확대만으로 원래 주소로 풀 수 있다고 가정하지 않는다. 필요한 경우 bounds/zoom별 주소 핀 조회를 추가한다.
- 지도 표시 정밀화 요청의 `view_bbox`와 통계에 적용된 `scope.bbox`를 분리한다. 자동 통계 갱신이 OFF여도 집계 클러스터를 확대해서 주소 핀을 불러오는 기능은 가능해야 하지만, 그것이 전체 통계 조건을 몰래 변경해서는 안 된다.
- 장소 상세 조회는 대표좌표와 동일한 작은 bbox가 아니라 `place_key`로 조회한다. 기존 `analyzePoint()`의 `[lng,lat,lng,lat]` 방식으로 같은 주소의 다른 좌표 신고를 놓치지 않는다.

#### UI와 호환성
- 장소 패널의 위도/경도 숫자·좌표 자세히/짧게·좌표 복사를 제거하고 전체 주소·주소 복사로 교체한다.
- ‘신고 장소 수’, 장소 목록, 개인 장소 수/표식, 선택 상태, 목록과 지도 모두 동일 주소 키를 사용한다. 서로 다른 주소의 공간 클러스터는 주소 장소 수 합으로 표시한다.
- `point_key`를 외부 계약에서 바로 폐기하지 말고 `place_key`/`grouping_version` 등 명시적인 확장·전환 방식을 사용한다. 원천의 `source_report_key`, 신고 번호, 수집 이벤트 식별키를 바꾸지 않는다.
- 주소 없음/좌표 없음으로 지도에 나오지 않는 건의 누락 사유를 분리한다. 지도 장소별 건수 합 + 사유별 미표시 건수 = 같은 모집단의 전체 건수가 성립하도록 중복 없는 분류를 둔다.

### R08. 적용 필터를 반전색으로 명확히 표시

지역 목록·법규·기관·담당자·상세 필터 등 어느 경로로 적용됐든, 적용된 조건을 상단에서 즉시 확인하고 해제할 수 있게 한다.

- 조건바의 ‘상세 필터’ 버튼은 활성 조건이 있으면 배경과 글자색을 확실히 반전하고 개수를 표시한다.
- 선택된 지역/법규/기관 컨트롤, 활성 지역 행, 상단 적용 조건 칩에도 일관된 활성 스타일을 사용한다.
- 기존 토큰을 이용해 `--filter-active-bg`, `--filter-active-fg`, border 같은 의미 토큰을 매핑한다. 전체 요소에 `filter:invert()`를 적용하지 않는다. 양 테마에서 대조가 선명해야 한다.
- 색만이 아니라 체크/‘적용 중’/개수/삭제 버튼도 제공한다.
- 상단 칩은 사람이 읽는 지역명·기관명·담당자 소속·법규·날짜로 표시하고 내부 key를 노출하지 않는다. 개별 × 해제와 ‘전체 해제’를 제공한다.
- 활성 여부는 `applied/requested scope`와 기본값의 비교로 계산한다. 편집 중 draft를 이미 적용된 필터로 표현하지 않는다. 미적용 변경은 별도로 표시한다.
- 조회 중에는 요청 조건과 마지막 표시 데이터 조건을 구분한다. 뒤로/앞으로 이동에서도 조건·색·칩·목록 선택이 맞아야 한다.
- 자기 자신으로 좁혀진 결과에 선택 옵션이 사라져 현재 조건이 ‘전체’로 오표시되지 않도록 selected option을 유지한다.

### R09. 기관/담당자 전환을 표 도구줄로 이동

기존 우측 헤더의 `기관 / 담당자`는 목록 종류 전환이다. 이를 보이지 않는 상세필터 안으로 옮기지 말고 **‘열 선택’ 바로 오른쪽**에 붙인다.

권장 도구줄:
`[기관·담당자 이름 검색] [열 선택] [기관 | 담당자] [경찰 구분: 전체 | 경찰 | 비경찰]`

- 명칭 선택/이름 검색과 기관·담당자 목록 종류 전환을 구별한다. 실제 기관/담당자 조건 선택이 필요한 다른 컨트롤도 같은 영역에서 접근 가능하게 한다.
- 작은 화면은 도구줄 두 줄로 자연스럽게 줄바꿈한다. 전환 버튼은 항상 첫 부분에 보이게 한다.
- 열 선택은 실제 체크박스 메뉴로 구현한다. 열 정의를 single source로 삼아 헤더·셀·colSpan·정렬·확장 표가 같이 동작하도록 한다. 단순 안내문은 제거한다.
- 기본은 주요 열 중심으로 조밀하게, 기존 세부 지표는 열 선택/확장 표에서 모두 접근 가능하게 한다. 이름과 소속을 제외한 숫자 열은 선택 가능하게 한다.
- 검색 입력은 즉시 표시하고 요청만 debounce한다. IME 입력을 보존한다. 종류/정렬/검색 변경 때 페이지를 한 번만 초기화하고 같은 요청을 중복 발행하지 않는다.
- 기관/담당자·검색·경찰 구분·정렬·페이지는 서버 전체 목록을 대상으로 한다. 현재 page나 dashboard 상위 100개만 필터링해 전체 결과처럼 보여주지 않는다.
- 경찰 여부는 현재 확인된 기관코드/분류 자료를 우선 사용하고 기존 호환 규칙은 명시적으로 유지한다. 미확인을 비경찰로 단정하지 않는다. 새 `agency_type` 조건이 필요하면 Scope/parser/RPC/client/schema/URL/개인 비교까지 구현한다.
- 기관 목록 단독 오류는 표의 로컬 오류로 표시한다. 전체 지도/차트를 제거하지 않는다. 오류를 ‘결과 없음’으로 위장하지 않는다.

### R10. 상세 필터 날짜 키보드 입력 복구

상단 날짜의 정상 동작을 보존하면서 상세 필터에서도 키보드로 연·월·일을 끝까지 수정할 수 있어야 한다.

- Dashboard의 close handler를 안정화하고, Drawer 최초 열림 focus와 키 핸들러의 최신 callback 참조를 분리한다. effect는 실제 open 전환에 맞게 초기 포커스를 한 번만 처리한다.
- draft가 바뀔 때마다 focus cleanup/restore→첫 버튼 focus가 재실행되는 것을 막는다. 의존성 경고를 무조건 끄거나 모든 의존성을 빈 배열로 바꿔 stale callback을 만드는 방식은 금지한다.
- 이전 포커스 요소는 열 때 한 번 저장하고 닫을 때 유효한 연결 상태를 확인해 한 번 복귀한다. Escape·Tab/Shift+Tab focus trap·배경 클릭 닫기는 유지한다.
- 값·임의 key·인라인 컴포넌트 정의로 input을 재마운트하지 않는다. 편집 중 숫자/불완전한 입력을 강제로 오늘 날짜 등으로 덮어쓰지 않는다.
- 날짜 유효성은 적용 시 검증한다. 역전 범위·존재하지 않는 날짜는 이해 가능한 메시지로 표시하며 draft를 버리지 않는다. 필요 시 blur 검증은 가능하나 매 키마다 적용/재조회하지 않는다.
- 정상 동작하는 상단과 공통 DateRangeInput/공통 검증을 재사용하되 값 편집과 실제 scope 적용을 분리한다. 기존 달력 선택도 동작해야 한다.
- Playwright 등의 `.fill()` 한 번으로만 통과시키지 않는다. 실제 숫자를 순차 입력하고 포커스가 다른 요소로 옮겨가지 않는지 확인한다.

## 5. 신규 분석 A01~A06: 기능과 서버 집계

현재 업로드 계약의 날짜·주소·기관·담당자·처리결과·처분·차량 원번호·법규·별점으로 구현한다. 차트 데이터를 만들기 위해 프론트에 비공개 신고 원본 배열을 보내지 않는다. server에서 집계 DTO만 만든다.

신규 분석의 기본 집합은 선택 기간에 답변 완료된 공유 신고이며 공통 지역·기관·담당자·법규 필터를 적용한다. 기존 신고량 그래프의 신고일 기준 등 기존 지표별 날짜 정의는 유지하고, 날짜 기준 선택 스위치를 새로 만들지 않는다.

### A01. 답변까지 걸린 기간의 분포

- `durationOf()`를 재사용하여 KST 달력 일수 차이를 계산한다. 날짜 없음·역전은 사유별 제외한다.
- 기본 동일 폭 구간의 히스토그램 또는 명확한 기간 범주 막대를 제공한다. 같은 날 0일도 포함한다. `1~7/8~14/15~30/...`처럼 폭이 다른 범주를 동일 폭 막대로 그릴 때는 ‘기간 구간별 건수’로 명명하고 정통 밀도 히스토그램인 것처럼 표현하지 않는다.
- 건수/집단 내 비중 전환, 전체/내 신고 비교, 유효 건수·중앙값 표식을 제공한다. 내 분포를 전체 건수 분모로 나누지 않는다.
- DTO 예: `buckets[{lower, upper, label, count, percentage}], valid_count, excluded, median_days, mean_days, p90_days`.
- 진행 중 신고의 완료 예측 차트로 설명하지 않는다.

### A02. 기관 × 위반법규 처리결과 히트맵

- 실제 교차 집계다. 기관별 통계와 법규별 통계의 곱이나 비례 배분으로 셀을 만들지 않는다.
- 행은 실제 기관, 열은 `lawKey()`로 정리한 조 단위 법규. 선택 기관 내부에서는 담당자 행으로 전환할 수 있다. 이미지의 ‘경찰청/지자체/도로공사’ 같은 예시를 고정 행으로 쓰지 않는다.
- 지표는 수용률/불수용률/과태료 부과율 중 선택. 각 셀에 분자·분모·표본 수를 연결한다. 결측은 0%와 다르게 표시한다.
- 기본 보이는 행/열은 적당히 제한하되 검색/페이지/확장으로 나머지에 접근하고, 부분 목록임을 표시한다. 법규 미상을 보존한다.
- 셀 클릭은 그 셀의 기관 또는 담당자+법규 필터를 원자적으로 적용하고 상단 칩을 즉시 활성화한다.
- DTO 예: `rows`, `laws`, `cells[{row_key,law_key,completed_count,outcomes,fine_count}]`, `total_rows`, `total_laws`.

### A03. 처리기간 × 처리결과 버블 산점도

- x=기관/담당자의 유효 소요기간 중앙값, y=선택한 과태료 부과율 또는 수용률, 점 크기=해당 기관/담당자의 완료 건수.
- 한 점의 tooltip에 소속·이름·날짜 유효 건수·전체 건수·분자·분모를 제공한다.
- 내 신고가 있는 기관/담당자는 테두리/기호로 구별할 수 있다. 사용자 기여 원시 목록은 공개하지 않는다.
- 표본 1건도 표시한다. 기간을 계산할 수 없는 기관/담당자는 x=0으로 강제 배치하지 말고 미표시 사유·개수를 보여준다.
- 기관 클릭은 기존 기관 필터, 담당자 클릭은 소속과 담당자 키를 함께 적용한다.
- DTO는 기존 entity 집계에서 필요한 값·전체 목록 coverage를 이용한다. 상위 100개 잘린 배열을 전체 산점도로 가장하지 않는다.
- ‘우수/미흡’ 사분면, 종합점수, 능력 평가를 추가하지 않는다.

### A04. 차량별 반복 신고일 분포

- 기본 지표는 단순 신고 횟수가 아니라 **서로 다른 신고일 수**다. 같은 날 같은 차량에 5건 신고되어도 1일로 센다.
- 같은 완료기간 집합 안에서, 유효 원번호를 `parsePlate()`로 정규화하고 신고 식별 중복을 제거한 후 차량별 distinct `report_date` 수를 센다.
- 1일 / 2일 / 3~4일 / 5일 이상 등 명확한 범주를 쓰고 y축은 차량 수다. tooltip에 차량 수·집단 비중을 제공한다.
- 2일 이상 신고된 차량 수/비중과 계산에서 제외된 번호·신고일 결측 수를 보여준다. 날짜가 없는 신고만 가진 차량은 1일로 넣지 않는다.
- 원번호·해시·전역 차량키를 브라우저에 보내지 않는다. 공개 DTO는 분포·분모만 제공한다. TOP5의 마스킹 문자열을 입력으로 계산하지 않는다.
- ‘재범률’, ‘단속 후 재위반율’이라고 표현하지 않는다. 기존 TOP5는 별도로 보존한다.

### A05. 월별 처리결과 비율 변화

- 기존 `TrendCard`의 건수 보기를 유지하고 처리결과 비율 보기를 추가한다.
- 수용률/일부수용률/불수용률/과태료 부과율 중 한 지표를 선택한다. 전체와 내 신고는 같은 기간·필터·dataset_version으로 비교한다.
- 월 기준은 `completed_date`. 각 월의 실제 분자/분모로 계산한다. 평균 비율을 다시 평균하지 않는다.
- 자료 없음은 null로 선을 끊고 0%와 구별한다. 미래·불완전한 이번 달 상태도 유지한다.
- 비율 차이는 %p, 건수 증감은 적절한 % 또는 건수로 구분한다. 가짜 추세선·증감값을 생성하지 않는다.
- DTO는 월별 outcomes, fine_count, completed_count와 개인의 대응 분자/분모로 구성한다.

### A06. 처리결과별 별점 분포

- 공개 허용된 유효 `rating` 1~5만 사용한다. 기존 숫자 별점과 consent 정책을 그대로 따른다.
- 가로 100% 누적 막대. 기본 전체/내 신고, 상세 행은 수용/일부수용/불수용/결과 미상이다.
- 각 행의 1~5점 건수·평가 건수·평균을 계산한다. 각 행의 분모는 그 행의 평가 건수다. 미평가·비공개를 0점으로 넣지 않는다.
- 평균이 같아도 분포가 다른 fixture를 준비한다. 데이터가 아직 없는 기간·집단은 0점 막대 대신 자료 없음으로 표시한다.
- DTO 예: `rows[{status, counts:[n1,n2,n3,n4,n5], rating_count, mean}]`.
- 별점 사유/신고 본문을 새로 수집하거나 공개하지 않는다.

### 공통 차트 UI

기존 ECharts를 재사용한다. bar/line/heatmap/scatter/tooltip/visualMap 등 필요한 모듈만 등록한다. 차트 init/destroy와 데이터 `setOption` 갱신을 분리하고, 컨테이너 resize에 대응한다. 테마 전환·범례·값 읽기·키보드/표 대체 보기·reduced motion·빈 결과·오류 상태를 구현한다. 실제 없는 이전 데이터로 그래프를 채우지 않는다.

## 6. 데이터 계약과 코드 배선

### 6.1 공통 흐름

```text
private 건별 신고/기여 자료
  → 현행 로그인·동의·열람 자격 확인
  → 원천 신고 identity 중복 처리(전체/내 신고 각각의 규칙)
  → 공통 scope + 원천 위치에 따른 현행 지역/bbox 필터
  → 기존 날짜별 집합(reported / done)
  → 주소 그룹 · 장소 상세 · 신규 분석 6종
  → public/private 응답 DTO(허용된 집계만)
  → Zod/API 검증 · client adapter
  → Dashboard의 일관된 displayed snapshot
  → 지도·KPI·차트·기관표·장소패널
```

권장 새 모듈 이름은 `server/places.ts`, `server/analyticsDistributions.ts`, `src/hooks/useDashboardData.ts`, `useViewportScope.ts`, `src/components/PlaceDetailsPanel.tsx`, `AnalyticsGrid.tsx`, `AppliedFilterChips.tsx` 등이다. **아직 존재하지 않는 제안명**이다. 현행 구조에 적합하면 통합하되 책임은 분리한다.

### 6.2 주소와 장소 상세 계약

개념 예시:

```ts
// 최종 이름/호환 버전은 실제 계약과 조정한다.
interface PlaceSummary {
  place_key: string;
  grouping_version: string;
  address: string;
  display_lat: number;
  display_lng: number;
  report_count: number;
  completed_count: number; // 표시 제거와 별개로 내부 분모 유지
  outcomes: OutcomeCounts;
  fine_count: number | null;
  warning_count: number | null;
}

interface PlaceDetail {
  dataset_version: string;
  scope: Scope;
  place: PlaceSummary;
  agencies: PublicEntity[];
  managers: PublicEntity[];
  // 전체 행 수/페이지 정보, 지원 여부, 결측 정보 등
}
```

- 기존 PublicPoint와 새 장소 타입을 연결할 때 serializer/schema가 새 필드를 제거하지 않는지 검사한다.
- 기존 `/points/{key}`를 확장하거나 `/places/{place_key}`를 추가하되 호환 전략을 문서화한다.
- 장소 상세·분포·히트맵의 반환값은 같은 scope/version에 속해야 한다. 집계 도중 버전이 바뀌는 race는 같은 DB snapshot 또는 명시적 version 재검증으로 처리한다.
- 기존 points 배열에서 보이지 않는 주소라도 정상 key 상세를 검증 가능한 방식으로 조회할 수 있게 한다. 프론트에서 bbox를 임의로 만들어 조회하지 않는다.
- places·charts·entities에 새 query params를 추가하면 server allowlist, Scope, client params, schema, URL, 개인 비교를 빠짐없이 수정한다.

### 6.3 DB 변경

신규 원천 업로드 없이 가능한 집계는 기존 fact에서 계산한다. 주소 정규화·대표 위치를 안정적으로 보존할 때만 주소 차원/보조 열/인덱스 등 비파괴적 migration을 추가한다.

현재 데이터가 있는 운영 환경을 전제로 null/구버전/backfill/재실행 안전성을 설계한다. 예전 migration을 고쳐 재실행하도록 지시하지 않는다. 원천 사실·consent·tombstone·신고 identity·기여 lineage를 변경하지 않는다. 주소 캐시·대표값 갱신은 데이터버전·공개 정책과 일관되게 처리한다.

실제 SQL에서 범위를 먼저 좁히고 필요한 집계를 수행한다. 현재 fact 조회 상한·쿼리 시간 예산을 무조건 늘려서 해결하지 않는다. 주소·기관·기간 조합의 적정 인덱스와 query plan을 확인한다. 브라우저에 모든 원천 신고를 내려보내는 지름길은 금지한다.

### 6.4 버전·개인 비교·보안

- 현행 카카오 로그인, 활성 동의, 지도 열람에 필요한 공유 신고 수 기준을 유지한다. 사전 검토 시점 기준은 10건이다. 표시 표본 최소 1건과 열람 자격 10건은 서로 다른 규칙이다.
- 전체는 같은 신고의 여러 기여를 현행 대표 규칙으로 1건 처리하고, 내 신고는 계정별 중복 규칙을 유지한다. 주소 묶음을 새로운 신고 중복 제거로 사용하지 않는다.
- 담당자 전체 성명과 기관 표시를 보존한다. 차량 마스킹은 최신 `PROJECT_RULES.md`의 함수를 재사용한다. 과거 규칙으로 되돌리거나 시안의 원번호를 복제하지 않는다.
- 정확 원천 좌표는 비공개/기존 허용 저장 경로에 그대로 두고 새 UI는 주소 대표점을 표시한다. 이를 익명화 처리라고 설명하지 않는다.
- service_role/secret/raw token은 서버 안에만 둔다. 새 조회 endpoint에도 기존 viewer 검증·CORS·rate limit·no-store 정책을 적용한다.
- 이전 성공 결과 유지용 메모리는 로그인 세션 안에서만 사용한다. 공유 CDN·localStorage에 개인 응답을 캐시하지 않는다. 로그아웃/401/403/계정 전환 시 모두 정리한다.
- 실데이터 실패를 demo로 바꾸지 않는다. demo/fixture는 명시된 모드에서만 사용한다.

## 8. 검사·완료 정의

현재 package scripts 기준 `npm test`, `npm run build`, `npm run scan`을 실행하되 시작 시 실제 package manager/lockfile을 확인한다. 존재하지 않는 lint/e2e 명령을 실행했다고 적지 않는다. 기존 브라우저 자동화·호스트 제공 도구를 확인하고 필요한 regression test를 실행 가능하게 추가한다.

`ACCEPTANCE_TESTS.md`의 R01~R10, A01~A06, P01~P08을 전부 통과시키거나 실패/환경 차단 이유를 개별 표시한다. 인증·실 카카오 키가 없는 fixture 검수와 실제 SDK 검수를 구분한다. mock SDK 테스트만으로 실지도 검수 통과라고 주장하지 않는다.

최종 산출물:
- 실제 제품 코드·비파괴 migration 및 필요 배포 파일.
- 기능→파일→서버 DTO→테스트→브라우저 증거의 추적표.
- 390/768/1440/1920 폭 및 라이트/다크의 화면 캡처.
- 지도 반복 이동 시 네트워크·페이지 reload·지도 instance 생성/파괴 횟수 증거.
