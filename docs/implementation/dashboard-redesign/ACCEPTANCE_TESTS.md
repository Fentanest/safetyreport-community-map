# 필수 인수·회귀 테스트

`IMPLEMENTATION_PROMPT.md`와 함께 사용한다. 아래 수치는 전부 합성 fixture이며 실제 지역·기관·차량의 실적이 아니다. 각 항목에 테스트 파일, 실행 명령/환경, 결과, 화면·Network 증거를 연결한다.

## 2. 핵심 회귀 fixture

### F01. 지표 단위와 가중합

같은 클러스터에 다음 두 장소가 있다.
- 장소 A: 완료 1건, 수용 1건, 불수용 0건, 과태료 1건.
- 장소 B: 완료 9건, 수용 0건, 불수용 9건, 과태료 2건.

전체 결과 확인은 10건이다. 클러스터 수용률은 10%, 불수용률은 90%, 과태료 부과율은 30%여야 한다. 수용률 50%를 반환하면 실패다. 색상 함수에 들어가는 값은 각각 0.1/0.9/0.3이다. 프론트 공간 클러스터와 서버 상한 집계의 결과가 일치해야 한다.

추가 fixture는 0%, 10%, 50%, 90%, 100%, 분모 0(null)을 포함한다. null을 0%로 표시하지 않는다. 수용/불수용 전환 시 같은 완료 건수라는 이유로 핀 표시가 동일하게 남지 않는다.

### F02. 계도

한 주소 완료 10건의 disposition이 warning 4, penalty 2, fine 3, unknown 1이면 계도 4건/과태료 3건이다. 범칙금을 포함하여 계도 6건으로 표시하면 실패다. 계도 필드가 없는 구 API 응답은 지원 불명/자료 없음으로 표시한다.

### F03. 주소 동일성과 구별

- 동일한 전체 주소 + 서로 다른 좌표 + 서로 다른 신고 20건 → 1주소/20신고.
- 앞뒤·연속 공백만 다른 동일 주소 → 같은 주소 그룹.
- 건물번호 10과 10-1 → 다른 주소.
- 시군구가 다르지만 도로명과 건물번호가 같음 → 다른 주소.
- 도로명·지번은 검증된 alias가 있을 때만 합쳐짐.
- 주소 null 5건 → 가짜 한 핀 또는 좌표별 1핀 5개로 나타나지 않고 주소 미확인으로 보존.
- 주소는 있으나 유효 좌표 없음 → 통계·목록에는 있고 지도는 사유가 있는 미표시.
- 같은 신고가 PC·모바일·다른 dataset에 중복 업로드됨 → 현행 신고 identity 처리 후 한 번만 계산.
- 여러 계정이 같은 신고를 기여함 → 전체와 각 계정의 내 신고가 현행 대표 규칙을 따름.

대표 위치는 정렬과 같은 scope의 요청 순서에 따라 흔들리지 않아야 한다. 주소 대표 위치가 경계 밖인 경우에도 원천 위치 기준 지역 통계를 옮기거나 삭제하지 않는다.

### F04. 1,000개 이상 장소와 확대

1,001개 이상 고유 주소를 만든다. 전국 단계의 서버 클러스터가 브라우저의 확대에서 정상적으로 주소 핀으로 해소되는지 확인한다. 단순히 서버 집계 중심점 하나를 확대해서 계속 같은 묶음만 보이면 실패다.

자동 통계 갱신 OFF에서 주소 정밀화가 필요할 때 지도 표시용 요청은 허용하되 KPI의 applied scope와 수치는 바뀌지 않아야 한다. 장소 상세는 표시 대표점의 bbox가 아니라 해당 place_key 전체를 대상으로 한다.

### F05. 포커스 실제 입력

Drawer 열기 → 시작일 날짜 요소 클릭 → 해당 브라우저의 날짜 세그먼트 이동 키를 이용해 연/월/일을 실제 키 입력으로 수정 → 종료일도 수정한다. 각 키 입력 뒤 `document.activeElement`가 날짜 input인지 확인한다. 정상적인 날짜 세그먼트 내부 이동은 허용하지만 닫기 버튼 등 다른 요소로 이동하면 실패다.

`.fill()`만 사용한 테스트는 이 회귀의 증거로 인정하지 않는다. 숫자 순차 입력 또는 실제 사용 동작의 녹화/스크린샷을 포함한다. 같은 테스트에서 종료일을 시작일보다 앞서 입력하고 적용했을 때 draft를 보존한 오류 안내도 검증한다.

## 4. 통합·성능·보안 P01~P08

### P01. 재마운트와 문서 navigation

최초 접근 후 지도 instance 생성·destroy 횟수와 문서 navigation 횟수를 측정한다. scope 변경 20회·지표 변경·핀 선택·테마 전환·보기 전환을 수행한다. 정상적인 데이터 갱신에서 지도 host가 재마운트되지 않아야 한다. React StrictMode 개발 검증과 production preview의 횟수는 구별한다.

### P02. 빠른 지도 이동과 stale response

연속 20회 이동을 debounce 시간 안에 발생시키면 마지막 확정 범위에 대해 한 번의 논리 갱신으로 합쳐진다. A 요청보다 B 요청을 먼저 완료시키고 A를 뒤늦게 완료해도 B가 유지된다. 한 논리 갱신의 실제 endpoint 수를 기록하고 차트 6종이 같은 원천 RPC 6개를 호출하지 않음을 확인한다.

### P03. rate limit·네트워크 실패 회복

429/Retry-After 10초 fixture를 반환한다. 10초 전에는 자동 재시도가 없고 화면·줌·이전 데이터는 유지되며 오래된 데이터임이 명확하다. 이 동안 여러 이동을 하더라도 대기 종료 후 최신 범위만 처리한다. 5xx·offline·AbortError·409도 각각 테스트한다. 409 재동기화가 무한 반복되지 않아야 한다.

### P04. 권한 상실은 이전 데이터 유지 예외

기존 화면이 있는 상태에서 로그아웃/계정 변경/401/403/동의 철회/열람 자격 부족을 재현한다. 공개·개인 관련 데이터와 메모리 캐시가 정리되고 접근 게이트로 전환된다. 다른 계정에 이전 내 신고가 나타나지 않는다. 외부 CDN·persistent storage에 개인 조회 응답이 저장되지 않는다.

### P05. 교차 컴포넌트 일관성

같은 scope/version/집계 기준에서 KPI·차트·기관표·법규표·주소 핀·상세값이 맞는다. 지역별 행을 합칠 때 시도와 시군구를 동시에 더하지 않는다. 서버의 잘린 상위 100개·현재 표 페이지를 전체 통계 분모로 사용하지 않는다. 갱신 중 이전 수치와 새 조건을 새 결과인 것처럼 혼합하지 않는다.

### P06. 개인정보·원천 보존·노출 검사

네트워크 응답·DOM·URL·빌드 결과에 service_role, access/refresh token, 전체 차량번호, 차량 연결 해시, 비공개 계정 식별자, 금지된 신고번호가 포함되지 않는다. 표시용 주소 묶음이 원천 lat/lng·주소·report identity를 바꾸지 않는다. 최신 차량 마스킹과 담당자 실명+기관 정책은 유지한다. 합성 테스트 데이터와 원시 fixture는 Pages 배포 결과에서 제외한다.

### P07. 실제 시각·입력 검수

390/768/1440/1920 폭에서 다크·라이트 모두 확인한다. 페이지 전체 가로 스크롤·잘린 버튼·비정상 고정 높이·큰 빈 박스가 없어야 한다. 상세 필터 반전색은 양 테마에서 즉시 보인다. 표 확장/열 선택과 차트 resize, 주소 상세 전체 나열, 폰트 가독성, 지도의 로고·출처 가림을 확인한다.

### P08. build·운영 전환

실제 package scripts로 test/build/scan 결과를 남긴다. 신규 DTO를 지원하지 않는 서버, null 필드, 빈 결과, 1건, 대량 자료를 모두 확인한다. migration→Edge Function→프론트의 적용 순서와 역순 호환/롤백 계획을 문서화한다. fixture 검수와 실제 카카오 SDK·운영 Supabase 검증 결과를 구별하고, 환경이 없어 수행하지 못한 검사는 ‘미검증’으로 표시한다.
