# 인수 테스트 — 날짜 기준·포커스 KPI·정렬·배치

버전: `single-date-dashboard-2026-09-29.1`

**아래는 앞으로 실행할 인수 기준이다. 체크리스트를 작성했다는 이유로 통과한 것이 아니다.**

각 ID마다 검증 환경, 코드 SHA, 실제값/기대값, 실행 명령, 증거 경로와 PASS/FAIL/PARTIAL/NOT_RUN/NOT_IMPLEMENTED/BLOCKED/N/A를 기록한다.
합성 fixture 기대값의 독립 검산과 실제 앱/SQL/브라우저 검증을 구분한다. 시간은 fixture에 고정하되 운영 시계나 운영 화면에 fixture를 주입하지 않는다.

## 중요한 oracle 해석

- 같은 기간에서 두 기준 모두 3건이지만 실제 identity는 신고일 A/C/E, 답변일 B/C/D로 다르다. **건수만 같은지 검사해서는 안 된다.**
- 신고일 기준 A의 9월 답변은 7월 신고월 결과에 포함된다.
- E는 답변 완료 확인 상태의 답변 날짜만 누락된 자료다. 신고일 기준에서 포함하고 답변일 기준에서는 제외한다.
- D는 답변일 기준에서 전체와 두 사용자의 내 신고에 각각 포함된다. 전체 고유 신고는1건이고 참여자는2명이다.
- 소요일수는 신고일 기준 [5,55]→중앙30일, 답변일 기준 [5,77]→중앙41일이다. 5월신고일을조회시작일로자르지않는다.
- oracle의 vehicle/place/agency key는 의미 없는 합성키다. 실제 테스트 helper로 변환하되 기대 membership과 산식을 바꾸지 않는다.

| EX-14 | 히트맵/범례/다운로드 | 전체/내같은축·색·숨김후분모불변·편집가능차트유지 |
| EX-15 | WASM/배포bundle | 지연로딩·비격리실행·공개번들비밀/fixture/서버코드유출없음 |

총 **99개 인수 항목**이다. 필수 기능별 세부 assertion은 실제 테스트에 더 추가할 수 있다.

## 보고서 필수 근거

수정 전/후 날짜 identity membership, SQL의 대표선정 순서, 같은 version의 반대 basis 지연응답 차단, 포커스 summary 전필드 일치, 전페이지 정렬, 두 기준의 월별/파일 parity를 우선 증명한다.
실제 SDK/Edge/PostgreSQL/Excel을 실행하지 못한 경우 원인을 명시하고 MOCK 또는 정적 코드 검사로 대체 통과시키지 않는다.
한 항목의 일부 assertion만 실행했다면 전체 항목 PASS를 붙이지 않는다. 스크립트 의도적 실패 자가 검증과 이전 실행 결과 비혼합을 유지한다.
